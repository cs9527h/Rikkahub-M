## 0.4.0 备份范围纠正：API 和所有设置必须能恢复
- **设置备份不是“去掉敏感字段”的便携配置导出**。恢复目标包含所有原生设置、AI API Key、供应商/模型、助手/人格/注入、网络代理、MCP 凭据、WebDAV/S3 配置、云服务器地址与偏好等。
- **必须区分“完整设置密文备份”与“不含凭据的分享/导出”**：旧 `BackupManager.portableSettings` 过滤 apiKey、password、secretAccessKey 等，无法满足用户要求。不得直接删除过滤后把完整机密明文写入 ZIP/上传网盘。
- 必须开发可跨设备解密的完整设置加密档案（推荐 AES-256-GCM + Argon2id 或 PBKDF2-HMAC-SHA256 + 随机盐/随机 nonce + 版本化头 + 完整性校验）；密钥/恢复短语独立安全保存，不写进 ZIP、不进入 GitHub/日志、不等同于云盘账号密码；提供 UI 设置、确认、恢复输入与遗失提示。自动备份须安全地获取本机加密密钥，跨设备须由用户提供恢复密钥/密码。更换密钥、安全擦除和迁移旧备份需明确测试。
- 云服务器设备 Token 由 Android Keystore 保存，不能原样备份加密值跨设备恢复；保留地址与配置元数据并在新设备重新配对（或经服务器正式迁移授权协议），明确告知用户这是设备授权例外，不得声称覆盖所有可移植凭据。
- **高频**：仅全量配置设置（含 API Key 的加密设置快照），不得有数据库/附件、图片及其它文件。理想情况下增加哈希去重、增量或保留有限历史版本。
- **低频独立**：聊天数据库按用户指定周期/手动选择，仍不含附件。两类备份不互相阻塞。
- **不备份附件**：自动备份绝不包含附件；手动导出可以显式选择，不得偷偷加入自动备份。
- 每条恢复路径（本地/WebDAV/S3）使用相同解析、解密、校验、预览、确认、原子恢复与失败回滚流程。密码错误/文件损坏/旧格式/网络失败须测试。
- 现有 PR 中只落了设置档案和频率隔离，**并没有实现 API Key 的安全加密恢复**；未实现前必须显示“凭据不会恢复”，严禁用不安全的明文备份冒充完成。
