# 新建与导入助手头像更换：裁剪图交付时序修复

## 用户问题与已定位根因

用户反馈角色卡导入/新增的助手更换头像失败。本轮不读取用户角色卡、聊天或手机状态；以代码控制流和合成文件回归定位。

旧时序：裁剪完成 → Unit callback → UIAvatar另起协程等待IO保存 → callback立即返回 → CropLauncher删除裁剪临时文件 → AvatarStorage读取源失败。AvatarStorage使用IO dispatcher，异步读取与提前删除存在真实竞态，失败时保留原头像而非替换，因此表现为“换不了”。

独立只读核验：新建和角色卡解析均使用随机助手ID；Navigation3为每个含ID的NavEntry提供独立VMStore。没有证据支持把本次故障归因于旧Koin VM或重复角色卡ID，未为此重构导航。

## 修复与不变量

- 裁剪交付callback改为suspend，UIAvatar不再fire-and-forget启动保存子任务；生产调用必须等待AvatarStorage复制完成。
- 新的交付helper负责写入/挂起消费/最终删除；源图在消费者整个挂起窗口存在，成功、写入失败、保存失败、取消及fatal均做临时清理。
- 临时文件名采用随机UUID，避免同毫秒多组件裁剪覆盖。
- 原头像generation、latest callback、pending保护、丢弃未提交图、锁内引用最终确认和原子隔离回收保持不变。
- 其他裁剪消费者同步复制聊天附件，适配suspend函数类型但不改变实际调用；不删除业务附件或用户源图。

## 回归与验证边界

- 新增5项JVM真实文件测试：延迟IO消费成功、消费者失败、写入失败不触发保存、挂起取消、fatal原样传播；断言临时文件存活和最后清理，不是源码字符串匹配。
- 为既有真实AvatarStorage Android fixture新增新建/导入两种助手的延迟复制流程：真实Room、DataStore、AvatarStorage、生产merge及同步回收，验证头像落盘持久化、临时图删除、其他助手不改、角色人格保留。
- Android新用例是生产保存链集成测试，不声称已经点击系统相册/实机裁剪，也不冒充完整Tavern解析端到端测试。
- 首次全量验证：主源码/Android测试编译成功，头像5项JVM通过；其他5个新增回归的异常类型/协程stacktrace recovery身份断言未通过，已保留日志并按真实类型及原始cause身份链修正，资源/回滚/请求计数断言未删除。等待最后全套执行及CI模拟器，不把这轮整体失败说成绿灯。
