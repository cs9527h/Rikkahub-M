# 文件删除与上游整合（1.1.6 之后）

## 证据范围

- 基于本地1.1.6后源码和上游`c08d7200`（2026-11-27）语义对比、针对性源码审查与回归；没有读取用户实际聊天数据库或测量实体手机删除耗时。
- 文件数量/关键词统计不是逐行审完全库的证据；这份记录只把有路径、触发条件或回归支持的项目当作已落实结论。

## 删除反馈

源码可确认：文件索引变化会触发全会话附件归属扫描，旧页面等扫描结果才更新；头像/未关联文件删除后又同步整个目录。未关联文件本身还有引用安全校验，因此这里不把“底层删除一定很快”当作实测结论。

- 删除真正成功后，页面立即按相对路径隐藏对应项；失败与仍被引用的文件保留，不提前假装删除成功。
- 只删除已有文件、会话和运行时引用未变时，复用剩余文件的归属结果，不再重解析所有历史。
- Room查询的`EXISTS`值不是内容版本。为每次会话表失效发射递增版本，即使行数/SQL结果相同，移动助手和替换同一消息仍强制刷新；被后续变更追上的扫描不缓存为可信结果。
- 初次进入时，让目录修复与目录订阅并行，不等修复完成才出首屏。
- 头像回收后只删自身索引行，不为每个文件重扫整目录；仍保留配置、数据库、收藏及运行时引用的复核。

## 头像回收原子性

- 设置流只监听头像签名；无待办候选的普通开关/滑杆保存不再全量同步。保留候选在其他引用消失后可重试。
- 不采用“锁外无挂起点所以没有并发”这类论证：其他线程能同时更新，且设置持久化本身会挂起。
- 当前方案把准备、路径检查、引用树扫描、mkdir、随机目标及最终unlink移到设置锁外；锁内保留最终设置身份/最新运行时确认和一次原子rename，将文件移到私有no-backup隔离区。
- rename失败保留原文件和索引；成功后原路径已退役，磁盘垃圾在锁外清理，进程中断残留可在隔离区按专用命名回收，不递归、不跟随链接。
- 运行时保护仍是最新快照观测点，不宣称持有全部运行时写入者的锁或阻止将来人为引用已退役路径。配置发射早于持久化的屏障继续保留。

## 上游功能

- APIMart图像/视频提供商、模型配置/能力及HTTP fixture回归。
- 手动压缩启动后在会话后台执行；关闭弹窗不取消已启动任务，失败归属原会话，停止生成仍可取消。
- 用户发送/重新生成时锚定对应用户回合；回复往下展开，拖动可打断置顶；返回底部先释放锚点和补白；保留键盘高度补偿。

- 连接测试使用模型提供商重写配置，录音时保持屏幕常亮，媒体任务默认5秒轮询。
- Shell可选步骤description移植到参数和展示层；等待审批时实际命令仍出现在摘要，完整输入详情保留，不用标题替代审批内容。此前把schema通用description关键词当成该功能已存在的判断已纠正。
