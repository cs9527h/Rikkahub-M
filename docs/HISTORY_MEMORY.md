# 历史提取与长期记忆

DeepSeek 和其他导入器先把会话存入本机。要从旧聊天建立长期记忆，在**助手 → 记忆 → 历史提取**选择目标库、会话创建日期和全部或指定会话。查看将要使用的模型服务和费用估算，确认后开始提取。

1. 按**此助手**或**全局记忆**选择保存位置。聊天从该助手当前启用的库读取。切换聊天模型不会改变库的位置。
2. 在候选列表检查用户原话、来源会话及相关旧记忆。可以编辑后新建记忆、合并到旧文件，或跳过。看见冲突时可打开旧文件修改，或标记为已过时。已过时的文件保留正文、出处和恢复入口。
3. 使用新聊天询问与记忆相关的问题。在**使用记录**查看最近 50 轮请求组装时的命中、注入片段、已返回到请求的工具读取和耗时。模型是否采用这些内容无法从请求记录判断。

## 授权、计费与备份

- 建立任务前只读取本机元数据。授权后，应用向确认页列出的模型服务按批发送用户文字，包括选定会话的本机编辑分支。附件、助手回复、人格提示词与现有记忆库不随提取请求发送。
- 提取请求使用独立的 HTTPS 客户端配置，并关闭正文调试日志和重定向。任务保存已确认的会话范围、目标库和模型配置指纹。来源会话改动或消失、设备授权失效或服务配置变动时，需要重新确认。
- 预估 Token 按已选节点的正文序列化体积和分批数量计算。可以填入提供商每百万 Token 的输入和输出价格来估算费用。运行时优先累计提供商返回的用量，缺少用量报告时使用近似值。断线、超时或应用在收到回复前退出时，重试可能再次计费。
- 审核后的 Markdown 文件继续使用现有设置和聊天备份。任务、未保存候选和召回记录保留在设备上，从应用导出的数据库快照和暂存恢复副本中清除。系统级备份依 Android 的既有规则处理，恢复的授权只在生成任务的设备有效。
- 可以在**设置**调整召回正文预算，或关闭**保存记忆使用记录**。使用记录页可以清除该记忆库的现有记录。

## 实现

- Room 35 → 36 只新增历史任务、候选、批次摘要和诊断表。会话、消息节点及记忆文件沿用原表。日常「做梦」仍走独立的七天窗口和单次处理限制。
- WorkManager 按目标库持久化执行。扫描以会话快照顺序、消息节点位置、节点 ID 和分段偏移推进。重复时间戳不影响游标。每批保存进度、候选和批次摘要处于同一个 Room 事务。
- 提取只允许模型生成候选。候选必须引用对应用户文字中的原句，通过人工审核才走现有的带版本写入入口。规范化摘要用于精确去重，相近记录列入人工对照。自动判断语义矛盾与自动取代旧事实暂不支持。
- 召回对同一库做分页本地关键词匹配，中文使用相邻字匹配，联合标题、别名、简介与正文排序。可选的 Markdown 重要性及更新时间参与排序。聊天把命中的有界片段作为背景信息，无工具模型也能收到这些片段。
- 当前只提取用户的文字陈述。由附件、助手回复或其他上下文才能确定的事实可能需要用户补录。召回做本地分页扫描，需要继续记录大记忆库在低端真机上的首字延迟。
