# 0.4.1 收尾：工作流与备份安全修复

目标：`0.4.1` / versionCode `16`，包名 `com.rikkahub.mate`，保持既有发布证书。PR #18 保持草稿，未授权绕过任何稳定版验收。

## 核查事实

- 原远端 head `27eb80d6`：编译与选定的备份仪器测试成功，截图 smoke 成功；模拟器性能作业失败。原工作流使用 `continue-on-error`，因此不能把主构建成功理解为性能验收成功。
- 官方 GitHub 设备授权已成功，当前 OAuth 具有 `gist/read:org/repo/workflow`。不再需要用户提供 Token，也不应再把缺少 workflow scope 作为现存阻塞。
- 历史推送失败的权限原因已解除。编辑工具曾报告替换片段匹配两处，属于非唯一的文本替换，不是 YAML 缩进错误；已使用唯一片段修复并通过 actionlint。
- 最新获取的 master 为 `44d64861`（中文默认文档），保留并发修改，不强推、不另开重复分支。

## 本批改动

### Actions

- 发布版本从硬编码 0.4.0 改为 0.4.1；APK versionCode 必须高于已存在的 code 15。
- 发布必须依赖签名构建与覆盖升级作业成功；取消升级、截图、性能作业的软失败处理。
- 稳定版本执行 `verify_release_acceptance.py`，检查真实设备、恢复、签名升级、性能及精确候选提交的记录。当前不存在完整验收记录，不能发布稳定版。
- 预览与发布增加 Android Lint、Python 门禁契约测试、所有应用仪器测试（不再仅选两个测试类），上传失败时的 JUnit、Lint、仪器报告及实际生成的 Room schemas。
- 密码/别名通过环境变量传入 shell，避免把 secret 表达式直接展开为 shell 源码；本地签名文件仅进临时工作区，权限 0600，不上传私钥。

### 数据安全

- 修复真实缺陷：设置备份导出 `memory.json` 时漏传 `deletedAt`，会使回收站记忆恢复为活动记忆。现完整导出该字段。
- 新增仪器回归：真实备份管理器加密导出→暂存→启动安装→Room 查询，验证已删除状态、命名空间、恢复操作及暂存后新增的数据库行保留。仅合成测试数据，不安装合成设置到应用真实 DataStore。
- S3 列表读取所有分页，不再把前 1000 条当完整列表参与清理。缺失/循环 continuation token、后续页失败或安全上限均直接失败，不返回部分列表执行删除。
- 两种存储清理路径及 worker 正确传播取消，每次删除前检查取消；不把 transport 异常对象写入清理日志，避免记录签名 URL 或凭据。
- 保留此前未提交的空间判断 helper 和四个边界测试，包括空间溢出拒绝。
