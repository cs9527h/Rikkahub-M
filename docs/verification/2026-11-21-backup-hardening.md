## 本轮已实现，等待新 Android CI

### 归档版本与完整性

- 新备份包含 `manifest.json`：格式版本、创建时间、应用版本、每个文件的字节数与 SHA-256。
- 在发布恢复暂存区之前验证全部归档文件，包括用户没有选择恢复的文件；拒绝清单与文件不一致、重复 ZIP 条目、路径穿越、非法版本、长度/哈希/CRC 异常。
- 有展开大小、清单大小和文件数量上限，并检查取消请求。
- 旧 ZIP 仍可恢复，但必须通过路径、重复项、大小和 CRC 检查。明文清单的 SHA-256 是损坏检测，不是密码学身份认证；仅外层 AES-GCM 提供认证加密。
- 创建与恢复共用归档互斥锁，保留原先 PendingRestore 暂存验证、原子发布与启动时安装流程。

### 自动备份禁止明文回退

- 自动备份必须使用用户显式保存的本机恢复口令；没有口令、密钥丢失或本机密文损坏时直接失败，绝不尝试明文上传。
- 口令在 Android Keystore 包装密钥下加密，密文保存在 `noBackupFilesDir`，不写入 Settings，也不进入任何备份归档。
- 页面默认仍只临时保留手动输入；另有明确的“保存口令供自动备份使用”操作。清除本机口令需确认，并暂停、取消自动任务；不会删除远端对象。
- 用户仍须另行保存原口令，跨设备恢复不能依赖原设备的 Android Keystore。
- 自动任务继续使用唯一 WorkManager 工作与指数退避；默认不含聊天附件/生成文件，并提供独立的最近自动成功时间和脱敏失败原因。
- 是否在自动加密备份中携带 API Key/连接凭据由用户明确选择，旧配置默认不携带。

### 不再把排除聊天附件误认为排除助手资料

- 不选择聊天附件时仍保存头像、助手背景、技能和字体；缺失的本机头像/背景会明确拒绝备份，不悄悄生成“完整”备份。
- 恢复只重新定位已知托管文件 URI，覆盖不同 Android 用户或旧包名的本机头像路径。
- 不修改人格/提示词正文、助手名称、ID、远端头像 URL 或任意用户文本。
- 备份选项文案明确区分“聊天记录与本地记忆”和“聊天附件与生成文件”。
