# Rikkahub-M 0.9.10 技术说明

发布日期：2026-11-25 ｜ versionCode 46 ｜ 上一版 0.9.9

按「与上游 RikkaHub 保持一致」的要求，把备份的加密层整个去掉：不生成、不读取、也不要求任何口令或密钥。

## 一、改了什么

| 面 | 0.9.9 及以前 | 0.9.10 |
| --- | --- | --- |
| 本机导出 | 用本机 Keystore 口令（或自定义口令）加密成 `RKMENC01` 容器 | 明文 zip（与上游一致），文件名回到 `Rikkahub-M-backup-<ts>.zip` |
| WebDAV / S3 手动备份 | 加密 | 明文 zip |
| 自动备份（设置/聊天两类） | `EncryptedBackupSession` 强制加密 | 明文 zip，不再读写密钥 |
| 恢复 | 先解密再解压 | 直接解压；**旧加密备份**仍会识别并要原口令 |
| 口令/密钥 UI | 导出问口令、自动备份口令、导出恢复密钥 | 全部移除；只保留「导入恢复密钥文件（仅用于打开旧版加密备份）」 |

保留的安全约束：

- **API Key / OAuth 等凭据仍然不进备份**（`includeCredentials = false`），
- WebDAV / S3 仍强制 https（`withHttpsByDefault` 与 `davReady/s3Ready` 检查），
- 备份文件本身不再加密——这是与上游一致的取舍。

## 二、速度

0.9.9 已经做了两件事（本版沿用）：

1. 恢复改为**流式读取**（`stageRestoreFromStream`），省掉整包复制到 cache 的一遍读写；
2. 去掉解压时**逐文件 fsync**（200MB 备份要刷上千次盘）。

0.9.10 又去掉了**解密**这一步：明文 zip 直接解压，200MB 备份少一整趟 AES-GCM 解密（PBKDF2 210k 派生 + 全量 GCM 校验）。

## 三、兼容性

- 无数据库迁移；versionCode 46，可覆盖升级 0.9.9；
- **旧加密备份仍可恢复**：`BackupCrypto.isEncrypted()` 会识别 `RKMENC01` 文件，此时才弹口令框（可无限次重试），
  或先「导入恢复密钥文件」再恢复；
- 新生成的备份在任何设备上都不需要口令/密钥，直接「选择文件 → 恢复」。
