# Rikkahub-M 0.4.4

发布策略：0.4.4 由 GitHub Actions 编译、JVM 单元测试、模拟器 instrumented 测试、Android Lint、签名/包名/versionCode 校验，以及从 v0.2.4 基准包覆盖升级到 0.4.4 的数据契约检查共同把关，不把未经真机验证的功能说成已验证，也不以真机验收 JSON 为强制门禁。未实测项目在文末如实列明。

## 备份与恢复：四标签合并为单页

- 备份页不再分「本地 / WebDAV / S3 / 提醒」四个标签，首屏就是：备份状态、立即备份、恢复备份、自动备份开关、存储位置、备份记录、高级设置。
- 存储位置（本机文件 / WebDAV / S3）改为一个选择页，选中后同一套「立即备份 / 恢复备份」直接作用于它，不再各自一份操作流程。
- WebDAV、S3 的连接参数和测试连接收在同一处；备份记录按本地 / WebDAV / S3 分组列出，支持恢复和删除，删除需要二次确认。
- 备份范围、自动备份周期、保留份数、恢复密钥移到「高级设置」，首屏不再堆配置说明。
- 原有能力没有靠删功能来“精简”：从 Chatbox / DeepSeek / Cherry Studio 导入、手动本机文件备份与恢复、远端备份记录列表都仍在。

## 日常零口令，但仍然加密

- 新备份不再要求用户创建、确认或输入备份口令。
- 首次备份时由系统用 CSPRNG 生成 32 字节恢复密钥（Base64url），用 Android Keystore 里的 AES-GCM 包裹后存在 `noBackupFilesDir`，不会进任何导出包；之后手动备份、自动备份、同机恢复都自动取用。
- 加密方式没有因为“免口令”而取消：备份内容仍为 AES-256-GCM、随机 nonce、版本化文件头。
- 换机或重装时，用「高级设置 → 恢复密钥」把密钥导出成独立文件（`RIKKAHUB-M RECOVERY KEY 1` 头 + 密钥），在新机导入即可恢复。界面明确提示该文件属于敏感材料，应与备份分开保存，不要放在同一个云端目录。
- 旧版口令加密的 `.rkmbak` / ZIP 归档继续兼容：只有确实缺少本机密钥、需要原口令时，才在恢复过程中询问一次；新备份全程不会出现口令框。

## 备份完整性与安全边界

- 默认备份聊天记录、助手配置、姓名与头像、人格提示词、长期记忆、设置、必要附件与文件。
- `apiKey`、OAuth、WebDAV/S3 密码、私有密钥等凭据默认排除；带凭据的归档必须加密，明文导出仍按原规则剥离密钥。
- 恢复前校验归档格式、清单、大小与路径，失败整批回滚，不动现有数据；恢复完成后提示重启生效。
- 自动备份一个开关接管（同时接管首页“该备份了”提醒），失败原因写入状态行，不再静默失败。

## 版本与兼容

- `versionName = "0.4.4"`，`versionCode = 19`，包名 `com.rikkahub.mate` 与签名证书保持不变，可直接覆盖安装 0.4.3。
- 单一 universal APK（arm64-v8a + x86_64），不发布分包。
- 设置文件新增的字段都有默认值；旧设置里已废弃的 `autoBackupIncludeCredentials` 会被忽略，不影响升级。

## 尚未验证（如实列出）

- 本轮没有真机验收记录：备份页交互、Keystore 密钥生成、恢复密钥导出/导入、WebDAV/S3 真实服务端恢复都只在代码与模拟器/单元测试层面验证。
- 国内备用更新源已部署并通过外部访问验证：`https://8.133.167.195/updates/manifest.json`（HTTP 200，TLS 证书含 IP SAN）与 `https://8.133.167.195/updates/Rikkahub-M-0.4.4.apk`（19,312,476 B，SHA-256 与 GitHub Release 一致）。服务器只新增只读 `location /updates/`，原有网关 `location /` 未改动。应用内自动切换到备用源的完整链路仍未真机走完。
- 真机性能指标（冷启动、滚动、内存）未采集，`docs/perf/baseline.json` 标记为未测量。
