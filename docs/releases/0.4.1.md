# Rikkahub-M 0.4.1 预览构建发布说明

> 状态：**pre-release（预览构建）**。真机验收未完成，因此不冒充稳定版；发布产物为 CI 构建的签名 universal APK，并带 pre-release 标记。

## 为什么要 0.4.1 而不是重发 0.4.0

已发布的 v0.4.0 使用 versionCode 15，且其启动路径仍会隐式删除旧本地聊天库与旧备份目录。0.4.1 使用 versionCode 16，可覆盖安装升级；本分支已移除该删除逻辑，并保留旧数据。已发布 v0.4.0 的 tag 与二进制资产不覆盖、不删除。

## 数据与备份

- 启动时不再删除旧 Mate 聊天库、WAL/SHM 或旧本地备份；这些数据保留在设备上，但不作为当前聊天数据源。
- 备份归档带版本化清单（SHA-256、大小、类型），恢复前校验完整性与路径安全；旧 ZIP 仍可读取。
- 支持客户端 AES-256-GCM 加密备份；含凭据的备份必须加密。自动备份没有本机口令时直接失败，绝不回退明文。
- 自动备份拆分为“设置/人格/本地记忆/必要资料”与“聊天记录”两类，按各自周期检查；内容与目标未变化时跳过上传，更换口令、账号或目标会强制重新上传。聊天附件不进入自动备份。
- 本地记忆删除改为“最近删除”，可恢复或永久删除；备份会保留回收站状态。
- 恢复在启动阶段、Room/Koin 初始化之前完成；设置类恢复把归档记忆合并进当时最新的本地数据库快照，不覆盖期间产生的新对话。
- 新版归档恢复前检查暂存分区可用空间，空间不足直接拒绝，不写入暂存区。
- 远端列表标注“设置备份/聊天备份”，避免选错恢复类型。
- 可选“保留最近 N 份自动版本”（默认全部保留）；只清理同类型自动归档，手动整包永远不会被自动删除。

## Grok 订阅登录（实验性）

- 登录、令牌刷新、模型目录、订阅额度查询与聊天请求沿用上游 RikkaHub 的实现：OAuth 设备码换 token，聊天走 `https://api.x.ai/v1/responses`，额度走 `https://cli-chat-proxy.grok.com/v1/billing`。
- 用户报告的 `Too many requests` + `Requests per Minute (actual/limit): 0/0` 属于服务端额度判定：该登录凭据在 api.x.ai 通道没有分配请求额度，不是网络故障，重试不会恢复。
- 本版把这类响应单独归类并给出明确提示（改用 API Key 计费模式，或等待 xAI 开放订阅聊天通道），不再无限重试、不诱导充值。
- 由于没有可用的真实 SuperGrok 账号与可出网环境，订阅聊天未能端到端验证，功能保留“实验性”标注。

## 通知与身份

- 前台生成通知使用会话自己的助手身份；找不到时显示应用名，不再冒充第一个助手。点击通知按会话区分。

## 明确的未完成项

- 全量真机安装/升级/恢复、性能对比、跨设备完整恢复、签名覆盖升级尚未完成。
- 自动保留清理为 opt-in，只在成功上传后执行；其网络删除路径尚未在真机/测试存储验证。
- Room 34→35 迁移仅有 SQL 级测试，缺 Room 完整 schema 校验（需要构建期导出的 35.json）。

## 证据边界

模拟器测试与 JVM 测试通过不等于真机验收；性能作业失败不能被整体绿色掩盖。发布前必须以同一提交的完整 CI、真机与性能数据为准。
