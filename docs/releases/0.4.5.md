# Rikkahub-M 0.4.5

发布策略：0.4.5 由 GitHub Actions 的编译、JVM 单元测试、模拟器 instrumented 测试、Android Lint、签名/包名/versionCode 校验和 v0.2.4→0.4.5 覆盖升级数据契约把关；不伪造任何验收记录，也不以真机验收 JSON 为强制门禁。未实测项目在文末如实列明。

## 修复：应用内更新提示“没有权限安装”

真机现象：0.4.3 在关于页点「立即更新」，下载与校验都通过后，系统提示 Rikkahub-M 没有权限安装，安装界面根本没起来。

原因有两层，两层都补了：

- **清单缺少 `REQUEST_INSTALL_PACKAGES`**。Android 8 起，应用要发起 APK 安装必须声明这个权限，否则系统直接拒绝，连「安装未知应用」的授权项都不会出现。0.4.5 已声明。
- **没有处理“未授权”这一状态**。以前代码校验通过就直接 `startActivity`，系统拒绝后用户只看到一个失败提示，不知道该去哪授权。现在：

  - `UpdateInstaller.canRequestPackageInstalls()` 用 `PackageManager.canRequestPackageInstalls()` 判定；
  - 未授权时不启动安装器，改为返回 `InstallPermissionRequiredException`，携带已校验通过的 APK；
  - 关于页弹出一次性说明「需要允许安装应用」，点「去设置」直接跳到本应用的「安装未知应用」授权页（个别 ROM 不认包名参数时退回应用列表页）；
  - 返回应用后（`ON_RESUME`）自动检查授权，已授权则立即打开系统安装器继续，不需要重新下载；
  - 下载并校验过的 APK 保留在缓存里，授权后直接复用。

仍然是“校验通过 → 系统安装器 → 用户确认”，没有静默安装，也没有绕过签名/包名/versionCode 校验。

## 其他

- **失败提示只留一处**：以前 `UpdateChecker.installUpdate` 会自己弹一个 Toast 并跳浏览器，界面上又显示一段失败文案，形成重复提示。现在失败原因只通过一个「更新未完成」对话框呈现，附「打开发布页」按钮；聊天页更新卡片这类没有对话框的入口才用 Toast。
- 更新对话框里保留 SHA-256 / 包名 / 版本号 / 签名校验的进度文案，下载完成会提示“校验通过，请在系统弹窗中确认安装”。

## 版本与兼容

- `versionName = "0.4.5"`，`versionCode = 20`，包名 `com.rikkahub.mate`，签名证书不变，可覆盖安装 0.4.4 / 0.4.3。
- 单一 universal APK（arm64-v8a + x86_64）。
- 国内备用更新源已同步 0.4.5：`https://8.133.167.195/updates/manifest.json`，APK 与 GitHub Release 同一 SHA-256。
