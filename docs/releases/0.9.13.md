# Rikkahub-M 0.9.13 技术说明

发布日期：2026-11-25 ｜ versionCode 49 ｜ 上一版 0.9.12

两件事：把备份里最后一点「口令/密钥」兼容代码彻底删干净；把本次会话改过的文件回看一遍，找同类 bug。

## 一、删除的加密/密钥代码

| 删除 | 原来干什么 | 现在 |
| --- | --- | --- |
| `BackupCrypto.kt` | `RKMENC01` 容器：PBKDF2(210k) + AES-256-GCM 加解密 | 删除；备份只有明文 zip |
| `BackupPassphraseStore.kt` | Keystore 包裹的口令文件（`backup-secret/passphrase.bin`） | 删除；不再生成或读取 |
| `BackupRecoveryKey.kt` | `RIKKAHUB-M RECOVERY KEY 1` 密钥文件编解码 | 删除 |
| `MissingBackupPassphraseException.kt` | 恢复时提示需要口令 | 删除 |
| `RestorePassphrasePrompt.kt` | 口令输入弹窗 | 删除 |
| `BackupCryptoTest` / `BackupRecoveryKeyTest` | 对应的 4+ 个单测 | 删除 |
| 仪器测试里的 4 个加密/口令用例 | 加密落库、口令保险库、损坏密钥回退等 | 删除 |

接口也一起收口：`createBackup`、`prepareBackup`、`stageRestore`、`stageRestoreFromStream`、`backupAutomatically`（WebDAV/S3）都不再有 `passphrase` 参数；`includeCredentials` 现在固定为 `false`（含凭据的备份直接拒绝）。

**注意**：0.9.9 及更早生成的加密备份从现在起无法恢复（加密实现已不存在），明文 zip 备份不受影响。

## 二、复核本次会话的 109 个改动文件

重点查「每次加载都覆盖用户数据」这一类（默认助手改名 bug 的根因）：

| 检查点 | 结论 |
| --- | --- |
| `SettingsNormalization` 的所有 `copy(...)` 改写 | 除已修的内置助手迁移外，其余都是「补齐缺失默认值 / 去重 / 清无效引用」，不覆盖用户填写的值 |
| `withBuiltInDefaults` 的 provider/TTS 过滤 | 只移除「推广位」与「缺 key 的 AiHubMix 占位」，用户自建 provider 不受影响 |
| `RikkaHubApp` 启动维护 | 12 个启动协程合并为 1 个延迟串行任务，每个任务只跑一次，失败只记日志 |
| `BackupManager` 恢复流程 | 暂存目录 `finally` 清理仍在；失败不写正式目录（`restore.publish` 是最后一步） |
| `FileTreeDelete` / `DocumentLimits` | 均有单测覆盖（软链不跟随、压缩炸弹上限） |
| `ChatList` / `ChatPage` / `ChatInput` 视觉回退 | 纯 UI 常量，无状态覆盖 |

除已修的助手改名外，**没有发现第二处同类问题**。

## 三、测试调整

- 删除与加密相关的测试后，`BackupArchiveFormatTest` 改为只认 `.zip`（`.rkmbak` 不再算备份），`BackupRetentionTest` 的 fixture 扩展名同步；
- `SettingsFieldsTest` 的「存储格式」金标准清单加入 `default_assistant_migrated`，样本中该字段设为非默认值，确保 Preferences 读写对得上；
- 全模块单测通过，脚本契约 69 例通过。

## 四、兼容性

- `Settings` 只新增了一个带默认值的布尔字段，**无 Room 迁移**；
- versionCode 49，可覆盖升级 0.9.12；
- 明文备份与原版 RikkaHub 互通（导出时可选「兼容原版」= 不含聊天库）。
