# Rikkahub-M 0.9.9 技术说明

发布日期：2026-11-24 ｜ versionCode 45 ｜ 上一版 0.9.8

这一版针对「备份/恢复时整屏铺色、没有进度、非常慢」的三条反馈。

## 一、界面：从整屏色块改成带百分比的对话框

改前：`busy` 时在页面顶部插了一张 `Card(containerColor = secondaryContainer)`，恢复 Sheet 还占 85% 高度；
在绿色系主题下整块面板就是"一大片绿"，且没有任何进度反馈。

改后：

- 恢复 Sheet 在开始恢复时立即收起（`showRecords = false`）；
- 统一的进度 `AlertDialog`：阶段文案 + `LinearProgressIndicator` + 百分比 + 「大备份需要几十秒到几分钟，请不要退出本页面」；
- 进度值来自 `stageRestore(onProgress)` 的字节回调，按 1% 节流更新，避免每 64KB 触发重组。

## 二、速度：两处真实开销

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 加密包读取 | SAF 整包复制到 `cacheDir`（写 200MB）→ 再解密到第二份临时文件（读写 200MB） | `stageRestoreFromStream`：从 SAF 读出即解密，只写一份 200MB |
| 解压落盘 | 每个文件 `output.fd.sync()`，200MB 备份意味着上千次 fsync | 去掉逐文件 fsync（暂存区是中间产物，进程被杀由 `PendingRestore` 清理重做） |

理论上 200MB 备份的恢复 IO 从约 800MB（复制+解密+解压+搬运）降到约 400MB，且去掉了上千次同步等待。

## 三、验证

```bash
./gradlew -Pandroid.aapt2FromMavenOverride=$AAPT2 :app:compileGithubDebugKotlin
./gradlew -Pandroid.aapt2FromMavenOverride=$AAPT2 :app:testGithubDebugUnitTest
python3 -m unittest discover -s scripts -p "test_*.py"
```

本机编译与单测通过；**恢复耗时与进度条实机表现需要真机验证**（建议记录一次 200MB 备份的导入耗时，
写进 `docs/perf/baseline.json` 作为后续回归基线）。

## 四、兼容性

- 无数据库迁移；versionCode 45，可覆盖升级 0.9.8；
- 旧的 8 位口令备份、无口令（本机密钥）备份都仍然可恢复。
