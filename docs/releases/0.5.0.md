# Rikkahub-M 0.5.0

发布策略：0.5.0 由 GitHub Actions 的编译、JVM 单元测试、模拟器 instrumented 测试、Android Lint、签名/包名/versionCode 校验，以及 v0.2.4 基准包覆盖升级到 0.5.0 的数据契约把关。不伪造验收，不以真机验收 JSON 为门禁；未实测内容在文末列明。

## 上游融合（RB 3.3.1 之后未同步的提交）

按 `docs/RM_VS_RB.md` 的十项缺口逐项审查，本版合入以下五项，均为最小范围移植并保留 RM 自身身份与发布链：

- `fbfb9926` **Google 兼容接口缺 `displayName` 时回退 `modelId`**：原来用 `!!` 取值，部分 Gemini 兼容服务不返回 `displayName` 会让整个模型列表解析失败。
- `48a68f87` **模型名最多显示两行**：长前缀的模型 ID 不再被截得只剩开头。
- `e4646a77` **Markdown 导出写入消息时间**：每条消息角色后附发送时间（按系统语言格式化到秒），方便回顾。
- `b7cf74dd` **Phone Use 识别被系统停用的无障碍服务**：区分“没开”和“开着但服务没运行”，工具调用前最多等 2 秒连接，仍失败则提示关闭重开并锁定后台；对应设置页提示同步。
- `358e2931` **bettertext 升级到 v0.1.6**：Markdown/代码高亮组件更新，随本版走完整 CI 回归。

明确不合入：上游版本号/包名、自动 tag 发布工作流、赞助与推荐供应商、空白 Issue 自动关闭工作流。RM 自己的签名、单一 universal APK、更新源与门禁不变。

## 性能（代码级热点治理，不含真机指标）

- **消息渲染的正则替换改为记忆化**：`ChatMessage` 以前在每次重组时对每条消息文案重新执行 `replaceRegexes`，既产生新 `String`，又让 Markdown 解析器把整段重新解析。现在按（原文, 助手规则）缓存结果，滚动、选择、打开菜单、流式过程中的无关重组不再触发重复替换和重新解析。
- 只做不改行为的缓存，没有删除动画、没有降低渲染质量、没有缩短消息内容。
- 未采集真机冷启动/滚动/内存指标，`docs/perf/baseline.json` 保持 `measured: false`，本版**不声明提升百分比**。

## 备份（保持冻结）

- 备份与恢复界面、免手输口令、Keystore 恢复密钥、自动备份、本地/WebDAV/S3、备份记录管理**均未改动**。
- 未重做备份流程，未照搬 RB 备份实现，未改归档格式与密钥机制。

## 更新系统

- 沿用 0.4.5 的安装权限修复：`REQUEST_INSTALL_PACKAGES` + 未授权时引导到「安装未知应用」并在返回后继续安装，已校验 APK 复用。
- 仍按 GitHub API → Atom → 国内备用源 → 本地缓存回退；备用源只接受固定签名与 SHA-256 匹配的包。
- 失败提示仍只出现一次。

## 版本与兼容

- `versionName = "0.5.0"`，`versionCode = 21`，包名 `com.rikkahub.mate`，签名证书不变，可覆盖安装 0.4.5 / 0.4.4 / 0.4.3。
- 单一 universal APK（arm64-v8a + x86_64）。
- 简体中文默认，保留英文与繁体入口。

- 无真机验收记录：安装授权跳转与返回续装、Phone Use 无障碍检测、Google 兼容模型列表在真实兼容服务上的表现、Markdown 导出的时间格式，都只到代码与 CI 层面。
- 无真机性能数据：冷启动、500/5,000/20,000 条消息滚动、流式帧率、内存峰值均未采集；本版性能改动只做静态热点治理。
