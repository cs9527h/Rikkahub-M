# Rikkahub-M 0.9.14 技术说明

发布日期：2026-11-25 ｜ versionCode 50 ｜ 上一版 0.9.13

一次全量复查的结果：三处真实问题 + 一批死资源。没有新功能。

## 一、修复：备份页还写着「文件已加密、必须用恢复密钥」

0.9.13 已经把加密代码删掉，但页面文案没跟上：

- 备份页本机区域仍写「文件本身已加密」「密钥保存在 Android Keystore…必须先用导出的恢复密钥」；
- 安全模式导入失败时还有一个「该备份已加密，请回到应用内备份页恢复」的分支。

现在改成：本机备份是普通 zip、不加密、不需要口令；换机直接拷文件导入；「兼容原版」导出原版 Rikkahub 也能导入。

## 二、优化：Markdown 网页预览的模板缓存

`buildMarkdownPreviewHtml` 每次点击「网页预览」都会 `assets.open("html/mark.html")` 读一遍 10KB 模板
（点击回调在主线程）。改成 `MarkdownWebAssets` 对象里缓存一次（`@Synchronized` 防并发重复读）。

## 三、清理：58 个未引用字符串（8 门语言共 459 条）

按「全仓 `R.string.X` / `@string/X` 引用扫描」找出 58 个零引用 key，从 `values*/strings.xml` 一并删除：

- 校验：8 个 `strings.xml` 全部通过 XML 解析；删除后反向扫描无悬空引用
  （仅剩 `android.R.string.ok` 与 flavor 目录里的 `phone_use_accessibility_label`，均非缺失）；
- 结果：`16 files changed, +42 −471`。

## 四、复核结论（本轮扫过的面）

| 面 | 结果 |
| --- | --- |
| UI 层阻塞 IO（`FileInputStream`/`copyTo`/`readText`） | 备份导出写入、ConversationExport、MediaCreation 保存、TextArea 导入都已在 `Dispatchers.IO`；本轮补上 Markdown 模板缓存 |
| `runBlocking` | 只剩 `RikkaHubApp` 的「有 pending restore 才执行」与 `WorkspaceDocumentsProvider` 的 DAO 查询，均有前置条件 |
| BackupVM 暴露的方法 | `recordLocalExportSuccess`/`loadBackupFileItems`/`testWebDav`/`testS3` 等逐个确认仍有调用方，无新增死代码 |
| 旧功能残留文案 | 已修上述备份页与安全模式两处 |

## 五、兼容性

- 无数据库迁移；versionCode 50，可覆盖升级 0.9.13；
- 备份行为与 0.9.13 一致（明文 zip、可选「兼容原版」导出）。
