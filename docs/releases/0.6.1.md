# Rikkahub-M 0.6.1

发布策略：0.6.1 针对真机 0.5.1 → 0.6.0 暴露的三个 P0 做代码级修复，由 GitHub Actions 的 JVM 单元测试、`lintGithubDebug`、签名/包名/versionCode 校验与 v0.2.4 基准包覆盖升级数据契约把关。GitHub Release 正文只放用户版说明，本文件保留技术细节。

## 三个 P0 与根因

### P0-1 应用内下载最终失败

- 根因：`UpdateChecker.downloadsOf()` 只生成一个下载地址。GitHub API 来源时该地址是 `releases/download/...`，会 302 到 `objects.githubusercontent.com`，国内网络经常超时/重置；没有备用源、没有重试、没有续传，`UpdateInstaller` 还在每次开始前删除已有文件，一次网络抖动就会落到「下载失败，点击重试」。
- 修复：检查源与下载源分离；下载统一按「GitHub 正式附件 → 已验证备用源 → 原检查地址」排序尝试；每个来源最多 3 次退避重试（1s/2s/4s），4xx（除 408/429）不再无意义重试；支持 Range 续传，校验 `206`、`Content-Range` 起点、`If-Range`（ETag/Last-Modified），服务端返回 `200` 或区间不合法时安全地从零重下；只有 SHA-256/包名/版本/签名校验失败才删除文件，网络中断保留部分供续传；下载使用独立 OkHttp 客户端（不设整体 callTimeout，连接 20s / 读 60s）。
- 安全门禁不变：SHA-256 → 包名 `com.rikkahub.mate` → versionCode 递增 → 与已安装版本签名证书一致 → 交给系统安装器由用户确认。未关闭 TLS 校验，未跳过哈希或签名。

### P0-2 通知栏没有下载进度

- 根因：`UpdateDownloadService` 的 `startForegroundService`、`startForeground`、`notify` 全包在 `runCatching` 里，异常被静默吞掉；Android 13+ 未授予 `POST_NOTIFICATIONS` 时前台通知不显示（只在系统任务管理器可见），应用却仍提示「请在状态栏查看进度」。
- 修复：启动前检查通知权限与通知开关，缺失时 `start()` 返回 false 并由下载状态回报界面；`startForeground` 失败记录诊断并停止服务，不再假装成功；通知常驻显示文件名/版本、百分比、已下载与总大小，总量未知时用不确定进度；提供「取消下载」动作；完成/失败各自发一条可点开的结果通知，随后 `STOP_FOREGROUND_DETACH`；通知权限被拒时更新弹窗内明确提示「进度仅在应用内显示」；通知、弹窗、关于页共用 `UpdateChecker.download` 单一状态源。

### P0-3 更新日志恢复成技术文档

- 根因（远程侧）：`release.yml` publish 步骤用 `--notes-file "docs/releases/${VERSION}.md"`，即技术发布说明全文，直接成为 GitHub Release body；0.5.1 的装机版 `updates.json` 只到 0.5.1，0.6.0 条目只能取远程 body 整段渲染。
- 根因（展示侧）：`MateChangelogPage` 直接把 Markdown 全文交给渲染器，没有分类结构，也没有过滤技术行。
- 修复：Release 正文改由 `scripts/user_release_notes.py` 从 `updates.json` 生成，发布前校验只允许「新增/优化/修复/其他」四个分类；技术说明保留在 `docs/releases/<version>.md`；`UpdateNotes` 统一解析与净化，远程纯技术正文解析为空则不再整段展示；内置条目优先，联网刷新不覆盖；页面按分类渲染、历史版本默认折叠可展开、刷新保留旧列表避免跳动。

## 同步修复

- 下载开始不再由 `downloadUpdate` 额外弹 Toast，状态由统一状态机呈现，避免同一次操作两条提醒。
- 失败原因区分 HTTP 403/404/429/5xx、域名解析失败、超时、连接中断，并在关于页提供「浏览器下载」入口。
- 取消保留已下载部分；关闭弹窗后可从关于页版本行回到进度；`Ready` 只在关于页拉起一次系统安装器，安装授权返回后复用已校验 APK。
- 已跳过版本不再主动提示，手动检查仍可看到。

## 测试

- 新增 `UpdateNotesTest`：四分类顺序、空分类隐藏、技术行过滤、纯技术正文不产出内容、摘要条数上限。
- 新增 `UpdateTransferPolicyTest`：`Content-Range` 合法/缺失/倒置/通配总量、续传起点匹配、4xx 重试判定、退避上限。
- 既有 `UpdateParsingTest`、`VersionTest`、契约测试继续运行。
- 模拟器：`upgrade` job 用 v0.2.4 基准包覆盖升级到 0.6.1，`scripts/upgrade_data_contract.py` 校验数据保留。

## 未在真机验证（如实列出）

- 小米 HyperOS 上后台限制、通知折叠、应用被系统回收后的下载恢复。
- 弱网/断网切换下的实际续传效果、运营商劫持场景。
- 安装授权被拒绝后再次返回的完整交互。
- 通知权限被拒绝时各 ROM 的提示差异。
- 真机性能数据未采集，`docs/perf/baseline.json` 保持 `measured: false`。

## 版本与兼容

- `versionName = "0.6.1"`，`versionCode = 24`，包名 `com.rikkahub.mate`，签名证书不变，可覆盖安装 0.5.1 / 0.6.0。
- 单一 universal APK（arm64-v8a + x86_64）。
- 备份系统未改动：界面、加密、WebDAV / S3 / 本地、旧格式兼容与历史数据均保持原样。
