# Rikkahub-M 0.5.1

发布策略：0.5.1 由 GitHub Actions 的编译、JVM 单元测试、模拟器 instrumented 测试、Android Lint、签名/包名/versionCode 校验，以及 v0.2.4 基准包覆盖升级到 0.5.1 的数据契约把关。未在真机验收的内容在文末如实列出，不写成已完成。

## 更新系统（P0）

- **下载进度接入界面**：百分比、已下载大小、总大小实时显示；服务端不给 Content-Length 时改用不确定进度条。
- **取消与重试**：下载可取消（会删掉半截文件），失败可一键重试，取消后状态回到空闲，不留残留。
- **后台下载 + 通知栏进度**：新增 `UpdateDownloadService`（`dataSync` 前台服务）。下载在 AppScope 里跑，服务只负责保活与刷新通知，界面、通知栏、聊天页卡片读同一份状态；关闭弹窗不再中断下载，通知里可直接取消。
- **单一状态源**：`UpdateDownloadState`（准备 / 下载 / 校验 / 就绪 / 失败）统一驱动界面与通知；下载中重复点击更新不会启动第二个下载，避免并发与重复文件。
- **校验不变**：SHA-256 → 包名 → 版本码必须更高 → 与已安装应用相同签名，全部通过才交给系统安装器；不静默安装、不绕过系统确认。
- **授权后继续安装**：已校验的 APK 在「安装未知应用」授权返回后直接复用，不再重新下载。
- **提醒去重**：同一版本在聊天页只提示一次，关掉后不再重复弹；「关于」页仍可手动检查。

## 安全模式数据抢救（P0）

- 安全模式页新增**导出完整备份**与**导入备份**入口，主界面进不去时也能把设置、聊天、附件导成一个 zip，之后在正常备份页导入。
- 备份数据库改为 `createDatabaseSnapshot`：优先 Room 的 `VACUUM INTO`，Room 打不开库（迁移失败、降级安装）时回退为**只读打开盘上的库文件**拍快照，保留原 schema 版本，恢复时再走迁移。两条路径都不改写原库。
- 导入先校验、暂存，下次启动在 Room 打开库之前替换；校验失败直接报错，不覆盖现有数据；恢复失败仍可回滚到原库（沿用既有 `PendingRestore` 机制）。
- 加密备份在安全模式下无法输入口令时明确提示回应用内恢复，不做半套解密。

## 更新日志

- 统一采用「新增 / 优化 / 修复 / 其他」四类，空分类不显示；每条一行、只写本版真实变化。
- 更新弹窗只显示两三行摘要并提供「查看完整更新日志」，完整内容在独立页面；技术细节留在 GitHub 发布说明。
- 历史版本只整理表达，不篡改发布事实。

## 备份（保持冻结）

- 单页备份与恢复界面、免手输口令、Keystore 恢复密钥、自动备份、本地/WebDAV/S3、记录管理**均未改动**；本版只加了上面那条数据库故障回退，属于真实缺陷修复。
- 未重做备份流程，未替换为上游备份系统。

## 版本与兼容

- `versionName = "0.5.1"`，`versionCode = 22`，包名 `com.rikkahub.mate`，签名证书不变，可覆盖安装 0.5.0 / 0.4.5。
- 单一 universal APK（arm64-v8a + x86_64），简体中文默认。
