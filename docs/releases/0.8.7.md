# Rikkahub-M 0.8.7

发布策略：在 PR #34（记忆中心内联设置、删除侧边栏入口）基础上做「单页化 + 召回正确性 + 全项目精简」。无数据库迁移，不动包名、签名与用户数据。

## 一、记忆中心：一个页面管到底

- 删除 `Screen.AssistantMemory`、其 nav entry 与 `AssistantMemoryPage.kt`：该页在 0.8.6 已退化成 `MemoryCenterPage(id)` 的一行壳，属于重复入口与死导航。助手详情与设置页都直达 `Screen.MemoryCenter`。
- 首页顺序固定为：使用状态（启用记忆 / 使用共享记忆库 / 自动做梦）→ 记忆库浏览 → 统计一行（记忆文件 / 待确认 / 已跳过 / 最近整理）→ 功能分组（整理：智能整理、从历史提取；审阅：确认记忆、已跳过、任务历史、使用记录；内容：搜索、新建）→ 记忆列表 → 高级设置折叠区。
- 三个开关是唯一开关定义（`grep enableMemory` 只剩 `MemorySettingsScreen.MemoryStatusSwitches`）；`enableMemory=false` 时另外两个禁用但仍显示当前值，避免「关了记忆顺手把共享也关了」的误解。
- 浏览 ≠ 实际使用：`MemoryCenterVM.scopePreference` 只影响页面，不写 `assistant.useGlobalMemory`；当浏览的库与实际使用的库不同，副标题显示「正在浏览另一份记忆库 · 不影响聊天设置」，并给出「回到实际使用的记忆库」。选回助手实际设置时 preference 归位为 null（重新跟随助手）。
- 高级设置：预算、整理模型、时间提醒、最近聊天参考、保存使用记录都收进 `MemoryAdvancedSettings`，`AnimatedVisibility` + 旋转箭头，`reduceMotion` 时直接切换不播动画。
- 搜索框从列表内的第一项改为钉在列表上方的输入框：点「内容·搜索」即展开并聚焦（先 `withFrameNanos` 等一帧，避免 FocusRequester 未初始化崩溃），返回键先关搜索。
- 去掉空状态固定高度（168dp 会裁掉按钮文案）与顶栏重复的「新建」图标；所有 chip 组用 `FlowRow` 适配 360dp、fontScale 1.3 与横屏。

## 二、召回与候选正确性

- **空库噪音**：原 `buildRecallPrompt` 在 0 命中时仍返回 5 行文本（"untrusted background records" + `[]`），开着记忆但库还空时每个请求都被塞一段空背景。现在由 `buildRecallInjection` 决定是否注入：空库且模型没有记忆工具时返回 null，消息列表原样返回（用例用 `assertSame` 断言同一实例）。
- **注入决策可测**：新增 `MemoryRecallInjection.kt`（`MemoryRecallStore` 端口 + `buildRecallInjection` + `withRecallInjection`），`ChatRequestFactory.buildStep` 只负责拼装；本轮召回结果（含「没有内容」）缓存在 TurnRecall 上，工具多步调用不再重复扫库。
- **跨任务候选污染**：候选表主键是 `(jobId, key)`，同一句话在两轮任务里各有一条。旧 `restoreSkipped` / `skipSelected` / `undoLastBulk` 用 `setStatusesOfScope(scope, keys, status)`，会把另一轮里已 saved 的那条一起打回 pending，已保存数掉下去还要求重审。改为按 jobId 精确更新，撤销记录增加 `jobKeys` 字段（旧记录缺该字段时自动回退原逻辑，JSON 向后兼容）。
- 0 命中轮次不再写使用记录噪音（这是不注入之后的副作用处理，需要时再把诊断与注入拆开）。

## 三、生命周期审计结论（8 条）

| 检查 | 结论 |
| --- | --- |
| 关闭记忆不注入 / 开启注入当前库 | 通过（修掉空库噪音） |
| 助手间记忆隔离 | 通过：作用域只取 `Assistant.memoryId`，A 的 prompt 不含 B 的记忆 |
| 手动保存后立即召回 | 通过：走真实 `MemoryRepository.writeFile`，关键词与改写问句都能召回；>16 条记忆时命中落在第二页仍能扫到 |
| 自动做梦确实执行 | 通过（调度器 20+ 用例 + `ChatService:832` 入口）；端到端用例在 `MemoryConsolidationEndToEndTest` |
| 关闭自动整理仍能召回 | 通过：开关两态注入文本逐字相同 |
| 关闭记忆不删文件 | 通过：删除只发生在删除助手与清空回收站两处显式操作 |
| 已跳过候选可安全恢复 | 通过（修复跨任务污染后）：恢复后 others 仍 saved，恢复再保存为 duplicate，不重复计费 |
| 共享记忆只在显式配置下使用 | 通过：global 时私有库一次都没被检索 |

## 五、性能

- 数据库微基准沿用 0.8.6 的模拟器记录（`LONG_CHAT_DB_PERF scope=query_only rows=1000 messages=2000 window=50 samples=100 before_median_us=218 before_p95_us=339 after_median_us=189 after_p95_us=243`，API 35 x86_64）。本次改动不涉及这些查询路径，没有重测就无法声称变化。
- 代码级改进（未量化为百分比）：召回结果在工具多步调用间复用（少一次扫库）、空库不再注入多余文本（少 token）、记忆中心所有 list 保留稳定 key。
- 真机性能仍未采集，`docs/perf/baseline.json` 如实标记。
