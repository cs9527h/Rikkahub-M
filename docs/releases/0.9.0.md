# Rikkahub-M 0.9.0

发布策略：这一版不再凭色值推算调 UI，而是先用 CI 模拟器截真实界面、做像素级测量，再按数据改。核心发现是一个被之前几版集体忽略的前提错误。

## 一、根因：默认背景根本不存在

`Assistant.useGradientBackground` 默认 `false`，`Assistant.background` 默认 `null`。于是 `AssistantBackground` 两条分支都不进，**什么都不画**，聊天页露出的就是 `colorScheme.surface`——浅色主题下接近 `#FFFBFE`。

截图实测（Pixel 6，1080×2400，浅色空态）：

| 区域 | 平均 RGB | 亮度 | 近白像素占比 |
| --- | --- | --- | --- |
| 顶部 0–8% | (247,244,251) | 246 | 96.9% |
| 中部 40–70% | (250,248,255) | 249 | **100%** |
| 白色横带扫描 | — | — | **y=900..1970 共 1070px 连续近白** |

这就是用户反复说的「大面积死白 / 像蒙了一层雾 / 没有层次」。0.8.8、0.8.9 我调的是 `MeshGradientBackground` 的色值——**那个组件默认根本不渲染**，所以前两版的背景调整对绝大多数用户完全无效。这版先修这个前提。

## 二、修复：`SoftBackground`

新增 `ui/pages/chat/SoftBackground.kt`，在「没有壁纸且未开动态渐变」时生效：

- 纵向三段：`lerp(surface, primary, 3%)` → `surface` → `lerp(surface, onSurface, 3%)`；
- 左上主色光晕 `alpha 5%`、右上暖色光晕 `2.5%`，都跟随 `colorScheme.primary/tertiary`，换主题或开动态取色自动协调；
- 全部走 `drawBehind` 静态绘制，**没有任何动画**，不增加滚动重绘成本；
- 暗色单独取值（`7%` / 光晕 `7%`），暗底上是「深蓝灰有一点点光」而不是提亮整屏。

第一版取值是浅色 `7%/9%`、暗色 `14%/13%`，截图实测顶部被压到亮度 217（基线 246）、暗色顶部从 23 升到 62——变成「顶部一块灰紫」，太重。按实测整体砍到约一半后收敛。

### 改前 / 改后（同一台模拟器，浅色空态）

| 指标 | 0.8.9 基线 | 0.9.0 | 变化 |
| --- | --- | --- | --- |
| 顶部亮度 | 246（96.9% 近白） | 233（0% 近白） | −13 |
| 中部亮度 | 249（100% 近白） | 243（0% 近白） | −6 |
| 整屏最亮处 | 249 | 245 | −4 |
| 近白横带 | 1070px 连续 | 无 | 消除 |

暗色：顶部 23 → 43、中部 19 → 24（保留层次，未出现发灰）。

## 三、正文排版

`ChatMessage` 原来直接用 `LocalTextStyle`（M3 `bodyLarge` = 16sp/24sp），叠上气泡 10dp 内边距后长回复行距过松。改为显式基准 `15.5sp / 22.5sp`（`CHAT_BODY_FONT_SIZE` / `CHAT_BODY_LINE_HEIGHT`），`displaySetting.fontSizeRatio` 仍按比例生效，用户自己调的字号不受影响。

## 四、引导卡

未配置模型时聊天页会显示 `QuickStartHeroCard`。截图实测它占 12%~36% 屏高（约 24%），首屏几乎只有一张大卡。padding 20→16dp、图标容器 56→44dp、行间距 16→12dp、标题 `titleLargeEmphasized → titleMediumEmphasized`。改后该区域平均亮度从 137（纯卡片）变为 218（卡片+背景混合），即卡片占比明显下降，信息一个不少。

## 五、截图流水线（本次新增基础设施）

- `scripts/capture-ui-screens.sh`：真机 `screencap`，按浅色/暗色各截「空态 / 输入态 / 发送后 / 抽屉」；
- `scripts/run-ui-capture.sh`：判定包名、安装、调用截图脚本（`android-emulator-runner` 的 `script:` 由 `sh` 解析，不能在 YAML 里写 bash 语法）；
- `.github/workflows/ui-screenshots.yml`：可装已发布 APK（做基线）或构建当前 ref，产物 `evidence/ui-<label>/*.png` 上传为 artifact，改到 `ui/**` 自动触发。

踩过的两个坑都写进脚本注释：主题切换后要等两拍再启动截图（否则会拍到半透明转场帧，实测出现过整屏亮度 95 的"浅色"截图）；`uiautomator` 只用于取发送按钮坐标，dump 出来的 XML 用完即删，不导出界面文字。

## 兼容与安全

- 无 Room 迁移（仍为 41）；聊天、记忆、人格、注入、附件、API 配置、备份设置一律未动。
- 包名 `com.rikkahub.mate`、签名证书不变，可覆盖升级 0.8.9；versionCode 36 / versionName 0.9.0。
- 未删除测试、未关闭 Lint、未放宽 CI 门禁。

## 未完成 / 需要明确说明

1. **没有真机验收**：所有截图与数值都来自 CI 的 Pixel 6 模拟器（API 35，x86_64）。真机（尤其 OLED、不同色温、动态取色）未验证。
2. **我无法直接看图像**：本次会话的模型不支持图片输入，因此没有"看图评价"，只有像素统计（分段平均色、亮度、近白像素占比、白色横带扫描）。这能客观回答"是否泛白/泛蓝/有白带"，但回答不了"好不好看"。
3. **消息气泡排版未截图覆盖**：CI 环境没有配置模型，截不到真实的助手回复气泡；正文字号的改动只有代码依据 + 组件级推理，没有截图证据。
4. 设置页、扩展管理、记忆中心、模型配置等页面本版未做视觉改动（0.8.8 已做过文案精简与对齐），"全局统一"只完成到聊天页这一层。
5. 真机帧率与耗电未采集；`SoftBackground` 是静态绘制，理论上不增加滚动成本，但未测量。
