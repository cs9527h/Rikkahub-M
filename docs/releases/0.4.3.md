# Rikkahub-M 0.4.3

发布策略：0.4.3 使用经 GitHub Actions 编译、单元测试、模拟器测试、Android Lint、签名及升级兼容性检查的 APK 作为正式发布候选；不再以真机验收 JSON 为强制发布条件。正式/预览状态以 GitHub Release 标记为准，未实测项目在文末如实列明。

## 更新系统

- 检查更新不再只看 GitHub REST：接口 403/限流时自动改用 GitHub 发布页（`releases.atom`，不受 API 限流），再退到国内备用源和上次成功的本地缓存。
- 修复解析：`tag_name`、`published_at`、`browser_download_url` 显式映射；更新日志不再出现“无法获取发布记录”。
- 更新日志内置当前版本说明（`assets/updates.json`），断网也能看；已发布的预览版本照常展示并标注“预览”，自动升级只挑正式版本。
- 下载更新后先校验 SHA-256、包名、版本号（必须高于已安装）和签名证书，全部通过才交给系统安装器，用户仍需在系统弹窗确认，不静默安装。
- 检查失败会给出可区分的原因：限流、拒绝访问、超时、DNS、备用源不可达。

## 关于页面

- 只保留：应用名称、版本号、检查更新、更新日志、联系作者、项目主页、开源许可。
- 去掉机型/SDK 行、重复的项目链接和冗长副标题；错误提示只保留一次。

## 备份

- 旧加密备份恢复时，仅当缺少本机密钥才弹一次原口令输入；日常备份与恢复不要求口令。

## 备用更新源

- 客户端预留 `https://8.133.167.195/updates/manifest.json` 作为备用源（当前未实际部署；使用 IP 的 HTTPS 证书还需完成主机名匹配验证），字段与 GitHub 一致并带 `sha256`。
- 服务端静态文件与上传脚本在 `tools/update-mirror/`；部署需要服务器 SSH 授权，本轮未部署，客户端在备用源不可达时自动回退 GitHub 发布页。
