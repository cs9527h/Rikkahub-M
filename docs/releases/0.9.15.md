# Rikkahub-M 0.9.15 技术说明

发布日期：2026-11-25 ｜ versionCode 51 ｜ 上一版 0.9.14

## 一、兼容原版导出：头像与 API Key 丢失

用户反馈：把「兼容原版」导出的包导入原版 RikkaHub 后 —— 助手在、附件图在，但**头像没了**、**API Key 与模型不可用**、聊天记录没有（这条是设计使然）。

三个原因彼此独立：

| 现象 | 根因 | 修复 |
| --- | --- | --- |
| 头像/背景丢失 | 原版 `BackupManager.stageRestore` **不做任何 URL 重写**，settings.json 里的 `Avatar.Image(url)` 原样写回；我们的地址指向 `com.rikkahub.mate` 的私有目录，原版（`me.rerere.rikkahub`）找不到 | 兼容导出时把托管文件引用改写到 `/data/user/0/me.rerere.rikkahub/files/...`（两边附件目录名一致：`upload` / `skills` / `fonts` / `media_creation`）；`BackupFileUris.relocateTo` 只改托管路径，网络图与 content URI 原样保留 |
| API Key / 模型不可用 | 我们之前的策略是「凭据一律不进备份」，`portableSettings` 会递归剥掉 `apiKey`、`oauth`、`customHeaders`，provider 只剩空壳，模型自然也用不了 | 本机导出现在 `includeCredentials = true`（与上游备份行为一致），恢复后不用重配；**WebDAV / S3 / 自动备份仍然剥离凭据**，不会把密钥传到云端；`webServerAccessPassword` 依旧清空 |
| 聊天记录没有 | 原版 DB schema 34、我们 41，Room 无法读取更高版本的库 | 设计使然：要带聊天记录只能用「完整备份」（仅本应用可恢复） |

验证：`BackupFileUrisTest` 新增用例覆盖「跨包名改写 + 非托管引用保持不变」；仪器测试里把原来的
`plaintextExportCannotCarryCredentials` 改为 `plaintextExportCanCarryCredentialsButBlanksWebServerSecret`。

## 二、聊天页左上/右上突兀的白块

`Theme.Rikkahub` 把 `android:windowBackground` 硬编码成 `#FFFEF7FF`（M3 基线近白）与夜间 `#FF141218`。
聊天页顶栏是 `Color.Transparent`，状态栏/刘海区域透出的就是窗口背景 —— 浅色主题下就是两块刺眼的白。
上游**没有任何 `themes.xml` 覆盖**，因此不存在这个问题。

修复：删除 light/night 两个 `windowBackground` 覆盖，窗口背景回到系统默认，页面底色继续由 Compose 主题绘制。
