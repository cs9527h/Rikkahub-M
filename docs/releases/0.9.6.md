# Rikkahub-M 0.9.6 技术说明

发布日期：2026-11-24 ｜ versionCode 42 ｜ 上一版 0.9.5

本版只做一件事：**备份导出 / 恢复不再卡死，并且能看到进度**。0.9.5 修掉了"选完文件不弹口令框"，
这一版修掉"弹了框之后界面冻住"。

## 一、根因：200MB 文件复制跑在主线程

`BackupPage` 里两个 launcher 都用 `rememberCoroutineScope()`（默认 Main 调度器）：

```kotlin
val scope = rememberCoroutineScope()          // Main
...
scope.launch {
    busy = true
    // 导出：把临时包写进用户选的 SAF 位置
    ...use { out -> FileInputStream(export).use { copyTo(out, it) } }
}
```

`copyTo` 是自己实现的 64KB 循环同步复制（`BackupPage.kt:823`），不是 suspend、也不切线程。
213MB 的包在 Main 上复制意味着：

- 界面完全不重绘 → 用户看到的就是「一直显示备份中，然后不动了」；
- 复制期间触摸、滚动、返回全部无响应，接近 ANR；
- 慢速存储（另一台手机、SD 卡、SAF 云盘）上要几十秒到几分钟。

恢复方向更糟：先把用户选的 213MB 文件从 SAF 复制到 `cacheDir`，同样在 Main 上。

## 二、修复

| 位置 | 改动 |
| --- | --- |
| 本机导出 | `vm.exportToFile()` 之后的 SAF 写入包进 `withContext(Dispatchers.IO)` |
| 本机恢复 | SAF → `cacheDir` 的读取包进 `withContext(Dispatchers.IO)` |
| Chatbox / Cherry Studio 导入 | 两处 `copyTo` 同样移入 IO |
| 进度 | 新增 `busyLabel` 状态 + 页面顶部进度卡片（`CircularProgressIndicator` + 「大备份需要几十秒到几分钟，请不要退出页面」） |
| 文案 | 按钮不再固定显示「备份中…」，改为阶段：「正在打包备份…」「正在写入文件…」「正在读取备份文件…」「正在解密并校验备份…」「正在下载并校验备份…」 |

原本就在 IO 上执行的部分保持不变：`BackupManager.prepareBackup` / `stageRestore` 内部都是
`withContext(Dispatchers.IO)`，解密（AES-GCM）、清单校验、解压、`fd.sync()` 都在后台线程。

## 三、跨设备恢复现在的完整步骤

1. 新手机安装 0.9.6；
2. 设置 → 备份 → 恢复备份 → 本机 → 「选择文件」，选 **`.rkmbak`** 包；
3. 页面顶部出现进度卡片，依次显示「正在读取备份文件…」「正在解密并校验备份…」；
4. 需要口令时弹框：输入备份口令，或粘贴「恢复密钥文件」第二行那串字符；
5. 完成 → 提示重启 → **重启 App** 才真正替换数据（替换发生在下次启动、Koin 初始化之前）。

## 四、仍然存在的已知限制

- 加密包恢复需要约 **2 倍包体**的空闲空间（解密临时文件 + 暂存目录），213MB 的包约要 430MB；
- 恢复仍需重启一次才生效；
- 本机导出的口令来自 Keystore，换机必须用「恢复密钥文件」——所以导出后请把密钥文件另存。
