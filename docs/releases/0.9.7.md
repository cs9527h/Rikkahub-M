# Rikkahub-M 0.9.7 技术说明

发布日期：2026-11-24 ｜ versionCode 43 ｜ 上一版 0.9.6

两份工作：把备份的加密策略改成「密钥优先、口令可选（≥6 位）」，以及把长期停更的国内备用更新源修好并接进 CI。

## 一、备份口令：密钥优先，口令可选

用同一个加密格式（`BackupCrypto`：`RKMENC01` + PBKDF2-HMAC-SHA256(210k) + AES-256-GCM），
只是口令来源有三条路径：

| 场景 | 口令来源 | 恢复方需要什么 |
| --- | --- | --- |
| 导出时不填口令（默认） | 本机密钥（Android Keystore 包裹，`backup-secret/passphrase.bin`） | 同机：什么都不用；换机：导入「恢复密钥文件」 |
| 导出时填口令 | 用户输入（≥6 位） | 只要有口令，**任何设备**都能恢复，不需要密钥 |
| 恢复时本机没密钥 / 密钥不匹配 | 弹框让用户输入口令 | 口令正确即可解密 |

实现要点：

- `BackupVM.exportToFile(customPassphrase)`：传入口令走用户口令，不传走 `withPassphrase(export = true)` 的本机密钥；
- `BackupArchiveFormat.exportPassphrase(...)`：把「留空 / 至少 6 位 / 两次一致」的校验集中在一处（原为 8 位）；
- `BackupPassphraseStore.save`：下限 8 → 6；
- 恢复：`stageRestore(passphrase)` 先用本机密钥；`MissingBackupPassphraseException`（没密钥）或
  `IllegalStateException("备份口令错误或文件已损坏")`（密钥不匹配）时，界面弹框让用户输入，最多重试 3 次；
- 本机恢复面板新增「导入恢复密钥文件」，与「选择文件」并排。

## 二、备用更新源：停更 8 个版本的原因

- 客户端回退链：GitHub API → Atom → 国内备用源（`https://8.133.167.195/updates/manifest.json`） → 本地缓存；
- 实际状态：服务器上 manifest 最后一版是 **0.8.3**（GitHub 已是 0.9.5），也就是 0.8.4 起的八个版本都没进备用源；
- 根因：`scripts/publish_update_mirror.sh` 的部署段用 `ssh "$HOST" "python3 - <<'PYREMOTE' ..."` 重建远端 manifest，
  嵌套 heredoc 经 ssh 传输时引号被吞，远端 python 直接 `SyntaxError: invalid character '：'`，脚本非零退出；
  而 scp 已经先跑完，所以现场看起来「APK 传上去了」，manifest 却一直停在旧版。
- 修复：远端重建改为「本地生成 `rebuild-manifest.py` → scp → ssh 执行」，并顺手把版本排序改成数值比较
  （原 `max(releases, key=version)` 是字符串比较，`0.10.0` 会排在 `0.9.x` 前面）。
- 补数据：已重新上传 0.9.5 并重建 manifest（12 个历史条目，含大小与 SHA-256 现算）。
- 防复发：`release.yml` 的 publish job 新增「Publish to domestic update mirror (optional)」步骤，
  配好 `secrets.MIRROR_SSH_KEY`（可选 `MIRROR_HOST`）后每次正式发布自动同步，并在结尾用 `curl` 校验线上 manifest 的版本。

## 三、验证

```bash
./gradlew -Pandroid.aapt2FromMavenOverride=$AAPT2 :app:testGithubDebugUnitTest
python3 -m unittest discover -s scripts -p "test_*.py"
bash scripts/publish_update_mirror.sh 0.9.5 /tmp/Rikkahub-M-0.9.5.apk --deploy
curl -sk https://8.133.167.195/updates/manifest.json | python3 -c "import json,sys;print(json.load(sys.stdin)['releases'][-1]['version'])"
```

本机结果：单元测试通过；脚本契约测试 69 例通过；备用源实测 `deployed latest: 0.9.5`，
线上 `manifest.json` 返回 200、`latest=0.9.5`、APK `Content-Type: application/vnd.android.package-archive`。

## 四、兼容性

- 无数据库迁移；versionCode 43，可覆盖升级 0.9.5 / 0.9.6；
- 老的 8 位口令备份仍然可以恢复（口令长度只限「新设置的」下限，解密不限）；
- 已加密的历史备份不需要重新导出。
