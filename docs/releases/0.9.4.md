# Rikkahub-M 0.9.4 技术说明

发布日期：2026-11-24 ｜ versionCode 40 ｜ 上一版 0.9.3

本版三件事：把大屏/横屏的布局判定换成 Material 标准、去掉两个「为零调用功能背整套库」的依赖、给 WebDAV 明文地址加可见提示。
没有新功能，没有数据库变更。

## 一、屏幕与形态适配

### 1. 大屏判定

| | 改前 | 改后 |
| --- | --- | --- |
| 规则 | `横屏 && 宽度 ≥ 1100dp` | `宽度 ≥ 840dp`（Material expanded 断点） |
| 竖屏平板（约 800dp 宽） | 落回手机布局，抽屉是要滑出来的浮层 | 固定侧边抽屉 |
| 横屏手机（700~900dp 宽） | 永远进不了固定抽屉 | 达到 840dp 即进入固定抽屉 |
| 折叠屏展开 | 取决于横竖屏与 1100dp 门槛 | 按展开后的实际宽度判断 |

实现：`ChatPage.kt` 的 `isBigScreen` 改为 `windowAdaptiveInfo.width >= 840.dp`；原来的「进入大屏时重置抽屉状态」逻辑保留（从横屏旋回竖屏不留残留浮层）。

### 2. 宽屏内容行宽

新增 `ChatLayout.kt` 里的 `CHAT_CONTENT_MAX_WIDTH = 840.dp`：

- 消息列表：`LazyColumn` 外面包一层居中 `Box`，列表自身 `widthIn(max).fillMaxWidth()`；
- 输入区：`ChatInput` 内部同样居中并限制到 840dp。

效果：1280dp 的平板上正文不再一行横跨整屏，消息与输入框左右对齐；手机（宽度 < 840dp）完全无变化。

**未验证**：本机没有模拟器/真机，布局改动只做了编译 + 单测 + 格式校验，实际观感需要 CI 的 `ui-screenshots` 或真机确认。

## 二、体积

| 移除项 | 证据 | 说明 |
| --- | --- | --- |
| `retrofit` + `converter-kotlinx-serialization` | `RikkaHubAPI` 是空接口，全仓零调用；Retrofit 只为 `create()` 它而存在 | 同时删掉 `DataSourceModule` 里两个 Koin `single` |
| `com.drew:metadata-extractor` | 全仓只有 `ImageUtils.getTavernCharacterMeta` 一处调用 | 换成 90 行的 `PngTextChunkReader`；新增 `PngTextChunkReaderTest` 4 例（tEXt / iTXt / 非 PNG / 无文本块） |
| `guava listenablefuture` 显式依赖 | 零 `com.google.common` / `ListenableFuture` 引用 | 只是去掉显式声明 |

具体 dex 减少量以 CI 产出的 APK 为准（本机缺 CMake/NDK，无法出包对比）。

## 三、启动与提示

- **启动**：`Application` 起进程时在 IO 线程调用 `warmUpRikahubPreferences()`，SharedPreferences 的第一次磁盘读不再发生在首屏绘制路径上。
- **备份安全提示**：WebDAV 地址以 `http://` 开头且已填写密码时，备份页显示红字「用户名与密码会以明文传输，建议改用 https://」。不拦下保存，不破坏现有配置。
- **工具链**：`lint { checkDependencies = false; disable += GradleDependency/NewerVersionAvailable/AndroidGradlePluginVersion }`。

## 五、兼容性

- 无数据库迁移，Room schema 不变。
- versionCode 40，可覆盖升级 0.9.3，签名与包名不变。
- 最低版本仍是 Android 8.0（API 26）。降级到 7.0 需要把备份/恢复/工作区的 `java.nio.file` 全部改写为 `java.io`，并为 51 个文件的 `java.time` 开启脱糖；收益 <0.3% 设备、风险集中在数据安全代码，本轮不做。
