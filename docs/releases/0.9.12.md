# Rikkahub-M 0.9.12 技术说明

发布日期：2026-11-25 ｜ versionCode 48 ｜ 上一版 0.9.11

## 一、内置助手改名被强制回退（真 bug，已修）

0.9.10 把内置助手从「李鱼 + 🐟」改成上游默认时，迁移写在了 `SettingsNormalization.withBuiltInDefaults()` 里，
条件是「id 是默认助手且名字是李鱼」，而这个函数**每次归一化都会跑**（设置加载、每次写入、每次启动）。

后果：用户把名字改回「李鱼」→ 下一次归一化立刻把它清空，看起来就是"改不回去"。

修复：

- `Settings` 新增 `defaultAssistantMigrated: Boolean = false`；
- 迁移条件加上 `!defaultAssistantMigrated`，并在迁移后置位；
- 新增 `AssistantMigrationTest`（3 例）：旧值迁移一次、迁移后可改回「李鱼」、全新安装不被误标。

## 二、让原版 RikkaHub 能导入我们的备份

原版无法恢复我们的备份，原因不是格式，而是**数据库版本**：原版 schema 34、我们 41，
Room 打开更高版本的库会直接失败。设置与附件其实是兼容的（目录名、`rikka_hub.db` 条目名、JSON 都一致）。

处理：导出时给两个选项

| 选项 | 内容 | 谁能恢复 |
| --- | --- | --- |
| 完整备份 | 设置 + 聊天库 + 附件 | 只有 Rikkahub-M |
| 兼容原版 | 设置 + 附件（不含聊天库） | Rikkahub-M 与原版 RikkaHub 都能导入 |

## 三、与上游的完整性对比

按文件级 diff（上游 `app/src/main/java/me/rerere/rikkahub` 488 个 kt vs 我们 533 个）：

上游有而我们没有的 12 个文件，全部是主动取舍：

| 文件 | 原因 |
| --- | --- |
| `RecommendedProviders.kt`、`Sponsor.kt`、`SponsorAPI.kt`、`SettingDonatePage.kt` | 去广告/去赞助政策 |
| `data/remote/RikkaHubAPI.kt` | 空接口，0.9.4 已删（连带 Retrofit） |
| `backup/tabs/{ImportExport,Reminder,S3,WebDav}Tab.kt` | 合并为单页「备份与恢复」 |
| `assistant/detail/AssistantMemoryPage.kt` | 记忆入口统一到设置 → 扩展管理 |
| `ui/hooks/Lifecycle.kt` | 我们用 `LifecycleEventEffect` 直接处理，无调用点 |
| `setting/components/CustomThemeButton.kt` | 自定义主题 UI 保留在 `SettingThemePage` |

我们比上游多 57 个文件（工作区/终端/Web 服务/记忆中心/媒体创作/加密备份等）。
