# Rikkahub-M 0.9.2 技术说明

发布日期：2026-11-24 ｜ versionCode 38 ｜ 上一版 0.9.1

本版没有新功能。内容是发布前的一次全量体检：把上一轮审计发现的安全问题补齐落地、把冷启动的串行化改造做完，
并给出安装包体积的实测构成（这一版没有为了瘦身牺牲任何已发布能力）。

## 一、功能可用性（静态核对）

没有运行环境（无模拟器 / 无真机）时不做「功能都能用」的结论，只做代码级核对：

| 检查项 | 方法 | 结果 |
| --- | --- | --- |
| 设置项是否有逻辑读取 | 对 `Settings.kt` 里 42 个 `Boolean` 设置逐项 grep 业务读取点 | 41 项都有业务读取；`developerMode` 只用于开发者页可见性，符合预期 |
| 设置界面与逻辑是否一致 | 抽查 `webServerJwtEnabled`、`webServerLocalhostOnly`、`autoBackupOnAppLifecycle`、记忆预算 | 一致；`webServerJwtEnabled` 的运行期生效问题已在本版修复 |
| 未引用资源 | 全仓引用扫描（52 个非 values 资源） | 2 个未引用捐赠图标 → 已删 |
| 零引用代码 | 符号级 grep（上一轮完成） | 5 个声明 + 1 个 DAO 方法已删，见 CHANGELOG |
| 上游差异 | 与 `origin/master` 及上游 rikkahub 的功能面比对 | 本 fork 的差异集中在 Mate 化命名、Web 服务、工作区/终端、记忆与备份；未发现被上游删除而本仓库仍在用的 API |

真机 / 模拟器验收项（通知、后台下载、跨设备恢复、无障碍）本轮仍未覆盖，不做结论。

## 二、安全修复（本版落地）

来自 2026-11-24 审计（`docs/audit/2026-11-24-full-security-and-deadcode.md`），全部带回归测试或编译验证：

1. Web API 鉴权开关改为逐请求判断（`WebApiModule.kt`）。
2. `/api/files/path` 收敛到四个用户内容目录（`FilesRoutes.kt`）。
3. `/api/events` 设置脱敏（`WebSettingsSanitizer.kt` + `WebSettingsSanitizerTest`）。
4. CORS 收敛、口令接口限速、上传总量上限、500 不回显内部异常。
5. 递归删除不跟随软链（`FileTreeDelete.kt` + `FileTreeDeleteTest`），覆盖工作区、文件管理、DocumentsProvider、rootfs。
6. 导出组件与外部 Intent 校验（快捷方式拍照、会话 ID、附件 URI）。
7. OOXML 解压体积与输出长度上限（`DocumentLimits.kt`）。

## 三、性能：冷启动串行化

`RikkaHubApp.onCreate()` 原来会同时抛出 12 个协程（临时目录清理、工具输出清理、工作区临时目录、工作区完整性校准、
上传文件同步、内置技能解压、启动计数写入……），在冷启动阶段和首帧、DataStore 首次读取抢同一块磁盘。

本版改动：

| 改动 | 目的 |
| --- | --- |
| `backup-restore` 目录不存在时跳过 `runBlocking(Dispatchers.IO)` | 绝大多数启动不再在主线程等待一次 IO 往返 |
| 维护任务合并为一个延迟 1.2 s 的串行协程，单步失败不影响后续 | 首帧与首屏列表不再和清理任务抢 IO/DB |
| `incrementLaunchCount` 移入维护任务 | 避免启动时 DataStore 写锁和 settings 首次读取互斥 |
| 会话页 `startScreen` 改为 `remember` | 重组不再重新生成 UUID、不再重复读 SharedPreferences，`rememberNavBackStack` 入参保持稳定 |

## 四、安装包体积：实测构成（0.9.1 基线）

用已发布的 `Rikkahub-M-0.9.1.apk`（19.4 MB）解包统计压缩后体积：

| 组成 | 压缩后 | 说明 |
| --- | --- | --- |
| `classes*.dex` | 8.9 MB | 业务 + 依赖代码，R8 优化已开启 |
| `lib/x86_64` + `lib/arm64-v8a` | 5.4 MB | sqlite3x / simple / ink / quickjs / proot / termux |
| `resources.arsc` + `res/` | 1.8 MB | 语言已按 `localeFilters` 收敛到 9 个 |
| `assets/` | 1.4 MB | mermaid（WebView 预览）、models_dev 快照、emoji 表、内置技能 |
| `static/`（Web UI） | 0.85 MB | 本地 Web 服务的预编译前端 |

本版删除未引用的 2 个资源；其余体积来自必需能力，**没有为瘦身砍功能**。可行但本轮不做的两项，留给后续决策：

- 发布版只打包 `arm64-v8a`：可省约 2.7 MB（15%），代价是 x86_64 模拟器 / ChromeOS 设备无法安装；
  与 README 承诺的「universal（arm64 + x86_64）」冲突，需要产品决定。
- 预压缩 `static/` 与 `assets/html`：预计省 0.3–0.5 MB，需要改 Ktor 静态资源读取与构建流程。

## 六、兼容性

- 无数据库迁移，Room schema 不变。
- `applicationId` `com.rikkahub.mate`、签名与 versionCode 递增关系保持，可覆盖升级 0.9.1。
- 新增行为变化（用户可感知）：
  - 局域网 Web 服务在「访问密码」开关打开后会立即要求登录（此前需要重启服务才生效）。
  - 上传接口单次总量上限 64 MB、最多 20 个文件。
  - 「拍照提问」快捷方式会先弹一次确认再打开相机。
