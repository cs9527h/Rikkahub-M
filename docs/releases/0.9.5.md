# Rikkahub-M 0.9.5 技术说明

发布日期：2026-11-24 ｜ versionCode 41 ｜ 上一版 0.9.4

本版修一个会让人「备份恢复不了」的 bug，把内置助手恢复成上游默认，并整块移除 Firebase Analytics。
无新功能、无数据库迁移。

## 一、备份恢复：三个真实问题

### 1. 加密备份选完文件后没有任何输入口令的机会（用户可见的根因）

`BackupManager.stageRestore` 原来的写法：

```kotlin
requireNotNull(passphrase) { "该备份已加密，需要恢复口令" }
```

`requireNotNull` 抛的是 `IllegalArgumentException`。而恢复页面的重试循环只捕获
`MissingBackupPassphraseException`（`BackupPage.kt` 的 `while (true)` 分支）：

```kotlin
try { vm.restoreFromLocalFile(temp, oneTimePassphrase); break }
catch (_: MissingBackupPassphraseException) { oneTimePassphrase = passphrasePrompt.ask() ?: return@launch }
```

两个类型对不上 → 异常落到最外层 `catch (e: Exception)` → 只弹一句「恢复失败：该备份已加密，需要恢复口令」，
口令框永远不出现。本机没有存储口令、或备份来自另一台设备/重装前时，100% 复现。

**修复**：该分支改为抛 `MissingBackupPassphraseException()`，界面按原设计弹框。

### 2. 口令输错一次就判死

`BackupCrypto.decrypt` 在 GCM 校验失败时抛 `IllegalStateException("备份口令错误或文件已损坏")`，
同样落到最外层 catch，用户没有第二次机会。

**修复**：本地恢复循环对这条错误也走「重新输入」，最多 3 次（`MAX_PASSPHRASE_ATTEMPTS`），
超限才提示「多次未输入正确口令，已取消恢复」。

### 3. 导出文件扩展名与内容不符

本机导出走 `withPassphrase(export = true)`，用的是 Keystore 里的口令，导出结果一定是
`BackupCrypto` 容器（文件头 `RKMENC01`），但文件名是 `Rikkahub-M-backup-<ts>.zip`。
用系统文件管理器点开只会得到「不是压缩包」，也容易让人以为备份坏了。

**修复**：默认文件名改为 `.rkmbak`；`BackupArchiveFormat.isBackupName` 本来就同时接受两种后缀，恢复不受影响。

### 4. 补一句必须说清楚的话

本机备份区新增提示：加密密钥存在本机 Android Keystore，**换机、卸载重装、清除应用数据后**必须用
「导出恢复密钥文件」得到的密钥才能打开这份备份；密钥丢了，备份无法恢复。

## 二、内置助手回到上游默认

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 名称 | `"李鱼"` | `""`（界面按 `stringResource` 显示「默认助手 / Default Assistant」） |
| 头像 | `Avatar.Emoji("🐟")` | `Avatar.Dummy` |
| `useAssistantAvatar` | `true` | `false`（与上游 `Assistant` 默认值一致） |

`SettingsNormalization` 增加一次性迁移：只把**旧版本写入的固定值**（名字「李鱼」或头像 🐟）改回默认，
用户自己改过的名字/头像不动。`StandaloneDefaultsTest` 期望值同步更新。

## 三、移除 Firebase Analytics

- 删除 5 个 `logEvent`：`ai_send_message`、`ai_edit_message`、`ai_regenerate_at_message`、
  `ai_tool_approval`、`ai_tool_answer`；
- 删除 `ChatVM` 的 `FirebaseAnalytics` 注入、`AppModule` 的 Koin 提供方、`app/build.gradle.kts` 的
  `implementation(libs.firebase.analytics)` 与版本目录条目；
- **Crashlytics 保留**，崩溃堆栈仍然上报。

## 五、给遇到「恢复不了」的用户的处理顺序

1. 升级到 0.9.5，重新选备份文件——现在会提示输入口令；
2. 如果提示「口令错误或文件已损坏」：说明本机 Keystore 里的口令与备份不匹配（常见于换机/重装后），
   需要用当时导出的「恢复密钥文件」导入后再恢复；
3. 如果提示「设备存储空间不足」：加密包恢复需要约 2 倍包体的空闲空间（解密临时文件 + 暂存），
   清理后再试；
4. 恢复完成必须**重启 App** 才会真正替换数据（替换发生在下次启动、Koin 初始化之前）。
