# Rikkahub-M 0.8.0

发布策略：0.8.0 交付长期记忆 2.0（批量审核、本地审核建议、可撤销批量写入、增量整理与预算门禁）、记忆首页重设计、召回相关性收紧，以及国内更新下载链路修复。由 GitHub Actions 的 JVM 单元测试、模拟器 instrumented 测试、Room 36→37 迁移、Android Lint、签名/包名/versionCode 校验与基准包覆盖升级数据契约把关。GitHub Release 正文只放用户版说明，本文件保留技术细节。

## 数据与迁移（Room 36 → 37）

- 只新增列与表，不删除、不改写任何已有数据：
  - `history_memory_job` 新增 `createdAt`、`finishedAt`、`budgetAckTokens`（`NOT NULL DEFAULT 0`）
  - 新表 `memory_scope_state`（整理水位、最近结果、当日已用估算 Token）
  - 新表 `history_memory_seen`（跨任务批次指纹）
  - 新表 `memory_bulk_undo`（批量操作撤销日志）
- 迁移把已 `finished` 的任务对应的记忆库水位设为迁移时刻：升级后第一次“整理我的记忆”不会把旧聊天再发一遍，也不会再收费一次。
- 未完成任务的游标、来源修订值、设备授权指纹原样保留；候选正文不再在状态变更时被清空。
- 备份策略修正：数据库快照仍会清除 `memory_recall`（本机使用记录），但**保留** `history_memory_job` / `history_memory_candidate` / `history_memory_batch`。恢复到其他设备时 `deviceConsent` 不匹配，任务会被置为暂停并要求重新确认，不会用旧授权上传聊天。

## 批量审核

- `HistoryMemoryDAO` 新增 `pendingAll`、`pendingSnapshot`、批量状态更新与撤销日志读写；审核页不再只看到前 50 条候选。
- `HistoryMemoryManager.saveSelected` 支持三种模式：只保存新事实、按建议执行、保存用户勾选项；逐条幂等，重复执行不会写出重复行。
- `MemoryTriageEngine` 为纯本地算法（无模型调用）：规范化文本后按中文二元组/英文词做包含度比较，排序出重复（忽略）、高度重合（合并）、同主题（更新）、负向表述冲突（确认）；`people` / `profile` / `decisions` 默认进入“需要确认”。
- 撤销：`memory_bulk_undo` 保存每个被写文件的“写入前内容”与“写入后哈希”。撤销时只有当前内容哈希未变才恢复，用户改过就跳过并如实计数；候选状态一并回退到 `pending`。
- 全部批量写入使用 `MemoryRepository` 的版本锁入口，单条失败不会中断整批，失败原因回传界面。

## 增量整理

- `prepareIncremental` 按 `memory_scope_state.lastOrganizedAt` 取 `update_at` 之后有改动的会话；没有新聊天时直接返回“无需整理”，不产生请求。
- 跨任务批次去重：批次内容的 SHA-256 写入 `history_memory_seen`，同一段聊天换任务也不会再次调用模型。
- 预算门禁在调用模型前检查：单次上限用 `estimatedTokens - budgetAckTokens`，每日上限用 `memory_scope_state` 当日累计；触发后任务置 `paused` 并写明原因，用户点“继续”才重新计算单次额度。

## 记忆首页与审核界面

- 单页结构：概况（已记住数量、最近整理、待确认数）→ 智能整理主操作 → 待确认卡片 → 搜索 → 按主题分组列表 → 最近删除 → 使用记录/高级设置。
- 审核页：建议筛选、全选/反选、保存选中、按建议整理、全部跳过、撤销；结果对话框分别报告新增/合并/更新/忽略/重复/待确认与失败原因。
- 删除、恢复、永久删除沿用既有软删除语义；过时记忆不参与召回。
- 长列表使用 `LazyColumn` 与一次性分组，候选和记忆都来自数据库 Flow，不在每次重组时读取全部文件。

## 召回相关性

- `memoryMatch` 改为分别统计标题类命中（权重 6）与正文命中（权重 2），并要求以下之一：整句出现、标题命中加至少一次正文命中、正文命中至少三次。
- 同标题的多份记忆只保留最相关的一条；排序加入重要性 × 3 与更新时间。
- 关联旧记忆推荐改为字面包含度 ≥ 0.3 且最多 3 条，不再用单关键词检索。

## 更新下载（国内网络）

- 部署侧：修复 `https://8.133.167.195/updates/manifest.json`，0.7.0 条目此前 `apkUrl`/`apkSize` 指向 0.6.1、`sha256` 却是 0.7.0 的真实值；已按磁盘上的 APK 重新计算大小与 SHA-256，并补齐历史版本。
- 客户端：
  - `UpdateParsing.manifest` 以版本号拼出的文件名为准，manifest 里文件名与版本不一致时改写为 `mirrorBase/Rikkahub-M-<version>.apk`，并丢弃不可信的大小。
  - 备用源下载地址一律要求 HTTPS。
  - GitHub API 的 `assets[].digest` 直接作为 SHA-256；缺失时回退读取同版本 Release 的 `SHA256SUMS.txt`。
  - 下载先写续传元数据再写正文：首次下载被中断后也能 `Range` 续传；`416` 时先校验本地文件，完整则直接使用。
  - 校验顺序改为“有哈希先校验哈希”，大小只在没有哈希时强制，避免错误的元数据拒绝正确安装包。
  - 存储空间不足不再被报成“网络中断”。
  - 关于页下载完成后不再立即清空状态：系统安装器被取消后可以再次点“安装”。

## 未完成与限制

- 没有真机数据：性能基线仍标记为未采集，长列表在 1000 条以上的真机流畅度需要后续实测。
- 增量整理按会话 `update_at` 水位判断；同一条会话被编辑后会从头解析（同批次内容仍会被全局指纹去重），没有做到“按消息区间增量”。
- 下载仍在应用进程的前台服务内进行，进程被杀后需要用户重新开始；没有迁移到 WorkManager。
