# Rikkahub-M 0.8.1

发布策略：0.8.1 是缺陷修复版。重点是找回 0.8.0 中误触「全部跳过」后看似消失的候选，补齐批量审核的确认与撤销入口，并为记忆二级页面补上统一转场。由 GitHub Actions 的 JVM 单元测试、模拟器 instrumented 测试（含 Room 37→38 迁移与 200 条候选恢复）、Android Lint、签名/包名/versionCode 校验与升级数据契约把关。

## 候选恢复（核心）

- 根因一：审核页「全部跳过」没有二次确认，一次点击把全部候选改为 `discarded`。
- 根因二：`persistConfirmedPlan` 创建新任务时 `clearCandidates`，取消任务时同样清空，旧候选失去归属。
- 根因三：完成对话框仅在 `changed > 0` 时显示撤销；跳过后 `changed == 0`，撤销入口被隐藏。
- 修复：
  - Room 37 → 38：`history_memory_candidate` 新增 `scope` 列并按任务表回填，候选归属不再依赖会被替换的任务行；新增 `(scope, status)` 索引。
  - 新建任务与取消任务不再删除候选与批次。
  - `restoreSkipped` 把 `discarded` 安全恢复为 `pending`，只改状态，正文、证据、来源原样保留，不调用模型。
  - 审核页新增「已跳过 / 已保存 / 重复」分类，可整批恢复或按选中恢复。
  - 完成对话框在跳过后也提供「撤销这次操作」和「恢复全部跳过」。

## 交互安全

- 「全部跳过」必须二次确认，并显示具体数量。
- 撤销入口依据实际存在的批量记录显示，不再绑定“有新增”。
- 保存、跳过、恢复之后重新读取建议与撤销状态，不靠界面缓存猜测。

## 页面转场

- 记忆首页、确认记忆、使用记录、高级设置使用 `AnimatedContent`：前进从右滑入、返回反向，标题与返回按钮随页面同步。
- 每个二级页保持自己的 LazyListState / ScrollState，切换不丢滚动位置。
- 读取系统 `ANIMATOR_DURATION_SCALE`，为 0 时改为无动画切换。
- 系统返回手势与返回按钮行为一致（`BackHandler` + 返回按钮都回到首页）。

## 从历史重新整理

- 普通「整理我的记忆」仍然走增量水位，只处理有新改动的聊天。
- 新增「从历史重新整理…」：显式选择日期范围与具体会话，显示模型服务、Token 估算与费用，确认后才发送。
- 相同批次内容仍由 `history_memory_seen` 全局指纹去重，不会重复计费；已保存记忆只会追加/合并，不会被覆盖。

## 验证

- `MemoryCandidateScopeMigrationTest`：37→38 迁移回填 scope，候选正文/证据/状态不丢。
- `HistoryMemoryBulkTest`：200 条候选全部跳过后完整恢复；任务行被替换后仍能按记忆库恢复。
- `MemoryTriageTest`、召回相关性、更新下载回归保持通过。
- 发布流水线包含 Android Lint、模拟器 instrumented、签名通用 APK 与升级校验。

## 未完成

- 仍无真机性能数据。
- 批量恢复没有单独的“最近一次恢复”历史记录，撤销依赖批量操作日志（恢复本身可通过再次跳过回退）。
