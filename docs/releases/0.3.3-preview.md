# Rikkahub-M 0.3.3-preview（测试预览版）

> 这是**测试预览版，不是稳定版**。已通过 GitHub Actions 的单元测试、签名通用 APK 校验与模拟器升级路径验证，
> 但**尚未在真机上完成**以下验收：云聊天端到端、取消/恢复、8MB × 4 附件、冷启动与长列表滚动、记忆编辑与审计。
> 若你需要稳定使用，请继续用 0.3.2，等待本版真机验收完成后再升级。

## 本版内容

### 云聊天与协议
- 与生产网关 0.7.2 对齐：`chat_version=4`，透传 `conversation_id`、`request_id`，请求体上限 1MiB。
- 能力协商以 `/capabilities` 为准：只有网关声明 `chat_versions` 含 4 才走隔离会话；`request_cancel` 才显示停止；
  `video_upload` 才允许选择 MP4；不支持的项不会用假按钮冒充。
- 请求取消：协程取消后用 `NonCancellable` 调 `/chat/cancel`，SSE 终态接受 `cancelled`；`type=done` 必须携带 `state=done`。
- 断线恢复：SSE 异常中断后回查 `requests/{id}`，校验请求前缀一致才续接，绝不自动重发造成重复消息。
- 409 错误按网关真实错误码翻译成中文提示（会话已有请求、请求 ID 冲突等）。
- 连接页新增「本轮注入诊断」与「查询最近一次请求」，可直接看到规则是否发出、请求最终状态。

### 人格与模式注入
- 导入支持 `.md` / `.json` / `.txt`：Markdown 不再报 “Not a JSON file”，按文件名作为注入名，UTF-8 BOM 自动剥离，空文件明确报错。
- 注入保序：相邻同 role 的规则合并为一个块，跨 role 的交错顺序不再被重排；支持 SYSTEM 角色与本地化标签。
- 云端规则真实生效：网关按会话写规则文件，AstrBot 插件在 `on_llm_request` 追加到系统提示词
  （生产已开启 `ASTRBOT_ORDERED_CONTEXT_V1=1`，实测规则文本进入模型请求并影响回复）。
- 本轮注入数量随请求回传，连接页可核对“发了几条”。

### 长期记忆
- 记忆详情弹窗、编辑、软删除、恢复、审计按能力开关显示，`memory_write` 未开启时不显示可写按钮。
- 列表失败不再清空既有数据；刷新先清后填，避免新旧混合。
- 历史 `importance>1` 的脏数据在服务端读取时归一（原始值单独保留），本版不批量改写。

### 会话列表与导出
- 会话列表按索引切片，不再全表扫描；仅在多选态构建 id 集合，仅在导出态构建选中消息。
- 备份/恢复的模拟器用例纳入 CI。

## 已知限制
- 云端人格/风格仍以服务器 `liyu` 人格为唯一来源；本版不覆盖、不合并 `default` 人格。
- 真机性能基线未采集，发布门禁按“未测量”记录，不做虚假对比。
- 旧版共享会话历史不迁移，按设备隔离后各设备从新会话开始。
