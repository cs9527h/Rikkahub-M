# Rikkahub-M 0.6.0

发布策略：0.6.0 由 GitHub Actions 的编译、JVM 单元测试、模拟器 instrumented 测试、Android Lint、签名/包名/versionCode 校验，以及 v0.2.4 基准包覆盖升级到 0.6.0 的数据契约把关。未在真机验收的内容在文末如实列出。

## 工程与发布链

- **仓库主页重写**：简体中文 / English / 繁體中文三个 README 统一结构（品牌封面、最新正式版区块、核心功能、当前状态、与上游区别、文档、许可），移动端优先，删掉 0.4.x 的过时版本说明与长表格。
- **README 自动同步**：新增 `Sync README release block` 工作流，正式 Release 发布后自动把版本号、APK 链接、大小、SHA-256 与摘要写回三个 README 的受控区块；只认 `draft=false && prerelease=false` 且同时带 APK 与 `SHA256SUMS.txt` 的发布，API 失败或哈希核对失败时保持上次内容，依赖 `[skip ci]` 与并发组避免循环触发。
- **CI 收敛**：`Daily Build` 改为只编译与测试的 `CI build`，不再产出 nightly 预览包、不再使用旧签名密钥；删除三份过期工作流（`promote-043-stable`、`mate-v1-preview`、`close-blank-issues`）。正式安装包只由 `release.yml` 通过全部门禁后发布。
- 契约测试同步更新，新增「只有 release.yml 允许发布 Release」的断言。

## 更新系统

- **跳过此版本**：聊天页卡片与「关于」页更新弹窗都支持跳过；跳过之后该版本不再出现在聊天页，仍可在「关于」页手动检查。
- 同一版本提示去重继续生效（关闭 / 跳过分别记录）。
- **残留清理**：超过三天的未完成更新包在启动时自动删除，不再占缓存。
- 下载进度、取消、后台下载与通知栏进度沿用 0.5.1 的统一状态机；SHA-256 → 包名 → 版本码 → 签名四重校验不变。

## 备份（保持冻结）

- 单页备份、免手输口令、Keystore 恢复密钥、自动备份、本地 / WebDAV / S3、记录管理均未改动。
- 0.5.1 的数据库故障回退快照继续保留；本版未改备份格式与密钥机制。

## 版本与兼容

- `versionName = "0.6.0"`，`versionCode = 23`，包名 `com.rikkahub.mate`，签名证书不变，可覆盖安装 0.5.1 / 0.5.0 / 0.4.5。
- 单一 universal APK（arm64-v8a + x86_64），简体中文默认。
