# Rikkahub-M 0.9.17 技术说明

发布日期：2026-11-25 ｜ versionCode 53 ｜ 上一版 0.9.16

## 一、删掉「兼容原版」导出

兼容包（不含聊天库）在原版 RikkaHub 里恢复不了聊天记录——原版 schema 34 读不了我们的 41。
一个「恢复了助手但聊天记录全没了」的选项只会误导，删掉。

现在导出只有一种：**完整备份** = 设置 + 聊天记录 + 附件 + API Key/OAuth（`includeCredentials = true`）。

删除的代码：

- `BackupFileUris.relocateTo()`（兼容导出时把头像路径改写到 `me.rerere.rikkahub` 目录）及其单测；
- `BackupManager.remapManagedAssetsTo()` / `UPSTREAM_FILES_DIR` / `upstreamPortable` 参数；
- `WebDavSync.prepareBackupFile(upstreamPortable)`；
- 页面上的「完整备份 / 兼容原版」选择对话框。

## 二、恢复页新增「导入原版 RikkaHub 备份」

原来的「从本机文件恢复」本来就能吃原版 zip（无 manifest → legacy 分支，逐文件 CRC 校验），
但入口名字没体现。现在恢复区是两个明确按钮：

| 按钮 | 用途 |
| --- | --- |
| 从本机文件恢复 | 本应用导出的完整备份 |
| 导入原版 RikkaHub 备份 | 原版的 `zip`（`settings.json` + `rikka_hub.db` + `upload/…`） |

两者走同一条 `stageRestore` 管线，差别只在文件来源；原版库会先落到暂存目录，再由 Room 跑
`Migration_35_36 … 40_41`（34 → 41）后发布，聊天记录、助手、附件一起恢复。
