# Rikkahub-M 0.8.2

发布策略：0.8.2 修复应用内更新下载与记忆召回两个 P0 问题，并收敛记忆/聊天界面的可读性与响应式问题。由 JVM 单元测试、模拟器 instrumented 测试（含 Room 38→39 迁移）、Android Lint、签名/包名/versionCode 校验与升级数据契约把关。

## 更新下载

- **多源顺序**：上次成功来源 → 国内备用源 → GitHub 正式附件 → 检查结果里的原地址；全部强制 HTTPS，不关闭证书校验。
- **连接更快失败**：连接超时 20s → 12s，每源重试 3 → 2 次；主源不可用时不再让用户干等一分多钟。
- **错误可解释**：新增 `UpdateSourceFailure` / `UpdateSourcesException`，弹窗列出「备用源：连接超时；GitHub：被服务器拒绝（HTTP 403）」，并给出重试与浏览器下载入口。
- **续传**：`.meta` 在写正文前落盘（首次中断也可续传），并记录该半截文件所属版本；版本变化不再拼接旧文件。
- **状态机**：失败/进行中重复点重试不会叠起两个下载；进程重启后 `activeInfo` 丢失时可重新检查再续；取消保留半截文件与来源。
- **可观测**：新增 `partialDownloadBytes`，用于提示「上次下载未完成」。
- 通知：前台服务进度百分比、剩余大小与取消入口保持单一状态源。

## 记忆召回

- 新增 `MemoryRecallEngine` 四阶段召回：
  1. 整句短语与别名精确命中；
  2. 中文二元组关键词命中（标题权重更高）；
  3. 语义近似（二元组包含度）与主题扩展；
  4. 按重要程度、更新时间重排，并按 Token 预算截取。
- 宽泛问题（「你记得我以前问过什么吗」）不再依赖两个字的巧合：识别为 broad 后按重要程度与最近更新兜底召回。
- 切词结果带 LRU 缓存（2048 条），连续对话不重复切词。
- 每条命中都有原因（标题命中 / 正文命中 / 别名 / 语义近似 / 重要程度 / 最近更新），写入召回记录。
- 召回记录新增：本轮问题、扫描条数、过滤条数、是否宽泛问题、过滤原因计数（Room 38 → 39 只增列）。
- 使用记录页展示上述诊断，并明确区分「找到」「注入」「工具读取」，不声称能判断模型是否采纳。

## 界面

- 记忆审核页：分类与筛选行支持横向滚动，窄屏/大字体不再溢出；批量操作区按状态只展示有意义的按钮。
- 聊天页：顶栏加向下淡出的底色，滚动消息不再与标题/按钮糊在一起；自定义背景遮罩加深，改善正文对比度。
- 背景图与渐变背景仍各自保留原有风格，不引入新的全局主题。

## 兼容与数据

- Room 38 → 39 只给 `memory_recall` 加列，历史记忆、候选、聊天、人格提示词与本地注入不变。
- 不重新提取、不覆盖 217 条已保存记忆；误解锁的候选仍可从「已跳过」恢复。

## 未完成 / 限制

- 无真机性能数据，长列表与冷启动仍需实测。
- 「语义近似」是本地字面包含度，不等价于向量语义；需要 Embedding 的增强未引入（避免额外付费与隐私外传）。
- 记忆页与聊天页仅做针对性重构，未重写全部消息渲染与后台绘制层。
