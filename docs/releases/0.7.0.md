# Rikkahub-M 0.7.0

发布策略：0.7.0 交付长期记忆的历史提取、候选审核与可验证召回。由 GitHub Actions 的 JVM 单元测试、模拟器 instrumented 测试、Room 35→36 迁移、Android Lint、签名/包名/versionCode 校验与 v0.2.4 基准包覆盖升级数据契约把关。GitHub Release 正文只放用户版说明，本文件保留技术细节。

## 历史提取

- 独立 WorkManager 任务，不在日常「做梦」的七天窗口内运行；按会话快照顺序、节点位置、节点 ID 和分段偏移推进游标，重复时间戳不影响进度。
- 支持按助手或全局记忆库保存；提取前读取本机元数据，只有用户确认后才把所选会话的用户文字发送到确认页列出的 HTTPS 模型服务。
- 分段按字符预算切分，超长会话可跨批次；单批失败记录原因并可重试当前批次，进程或应用退出后从持久化游标继续。
- 批次摘要按内容摘要去重，重复导入不会重复调用模型；候选保存前再做一次规范化文本去重。
- 只提取用户文字陈述；助手回复、附件、人格提示词与旧记忆不随请求发送。

## 候选审核

- 候选保存用户原句、会话 ID、消息 ID 与时间，人工确认后才写入现有 Markdown 记忆库。
- 可编辑、合并到已有记忆或跳过；写入使用带版本检查的现有入口，冲突时要求重新打开候选。
- 过时标记、软删除与恢复沿用记忆管理页；删除的记忆不参与召回，恢复后重新可召回。

## 召回

- 本地分页关键词匹配，中文按相邻字切分，联合标题、别名、简介与正文加权排序；可选的 Markdown 重要性/更新时间参与排序。
- 按正文预算截取片段，作为背景信息注入；支持无工具调用能力的模型。不同助手使用各自记忆库，全局库单独隔离。
- 使用记录保存本轮命中的路径、注入片段、工具读取、估算 Token 与耗时，保存在本机，不进入应用导出的数据库快照。

## 数据与兼容

- Room 35 → 36 只新增 `history_memory_job`、`history_memory_candidate`、`history_memory_batch`、`memory_recall`；会话、消息节点、记忆文件表结构不变，迁移测试验证旧聊天、旧记忆与软删除时间戳保留。
- 应用备份在生成数据库快照后清除任务、候选、批次与召回记录，保留已保存的 Markdown 记忆；恢复副本同样清理。
- 任务保存设备授权、模型配置指纹与来源修订值；设备授权失效、来源会话改动或模型/网络配置变化时要求重新确认。
- 备份、人格提示词、模型与服务商配置、更新检查与日志机制未改动。

## 测试

- JVM：候选证据过滤与精确去重、超长文本不截断代理对、中文别名召回、预算裁剪、软删除/恢复、跨库隔离。
- 模拟器：1000 个导入会话、单会话 5000 节点、相同时间戳、失败批次续跑、重复提取只生成一次记忆、候选合并冲突、备份剔除本地任务、Room 35→36 迁移。
- 契约测试：发布正文只允许用户四分类，内置日志不得出现开发过程章节。

## 未在真机验证（如实列出）

- 小米 HyperOS 后台限制对提取任务的影响。
- 真机性能数据未采集，`docs/perf/baseline.json` 保持 `measured: false`。
