# Rikkahub-M 0.9.16 技术说明

发布日期：2026-11-25 ｜ versionCode 52 ｜ 上一版 0.9.15

## 一、云端备份不再剥离凭据

0.9.15 只放开了「本机导出」，WebDAV / S3 / 自动备份仍在 `portableSettings(includeCredentials=false)` 下递归剥掉
`apiKey`、`oauth`、`customHeaders`。这一版统一为携带凭据：

| 入口 | 0.9.15 | 0.9.16 |
| --- | --- | --- |
| 本机导出 | 带凭据 | 带凭据 |
| WebDAV 手动备份 | 剥离 | **带凭据** |
| S3 手动备份 | 剥离 | **带凭据** |
| 自动备份（设置/聊天两类） | 剥离 | **带凭据** |

仍然清空的只有 `webServerEnabled` / `webServerAccessPassword`（Web 服务口令只在本机有意义）。
备份文件本身是明文 zip，请放在自己的私有存储里——这一点更新日志里也写了。

## 二、原版备份能不能全量导入我们？

**能，已经是全量恢复。** 依据：

| 项 | 数值 |
| --- | --- |
| 原版最新 master 的 Room 版本 | 34（`AppDatabase.version = 34`，commit eb417de2 实测） |
| 我们的 Room 版本 | 41 |
| 迁移链 | `Migration_35_36` → `36_37` → `37_38` → `38_39` → `39_40` → `40_41` 全部存在 |
| 恢复流程 | `stageRestore` 把 `rikka_hub.db` 落到暂存目录 → `DatabaseBackup.normalize` → `AppDatabaseFactory.create` 在副本上跑迁移 → 迁移成功才 `publish` 到正式目录 |

也就是说：原版备份里的 `settings.json`、`rikka_hub.db`（含聊天记录）、`upload/` 等附件都会被恢复；
原版**没有** `manifest.json`，走的是 `verifyDetailed` 的 legacy 分支（逐文件 CRC + 大小校验）。

所以「兼容原版导出」保留，不需要在 DeepSeek 导入里再加一个入口。

## 三、文案

- 导出对话框：`完整备份（设置+聊天记录+附件，仅本应用）` / `通用包（设置+附件，两边都能导入）`；
- 恢复面板：说明本应用的完整备份**和**原版 RikkaHub 的备份都能直接恢复，聊天记录会一起导入。
